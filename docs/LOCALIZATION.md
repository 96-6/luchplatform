# Язык интерфейса

Интерфейс поддерживает русский и английский языки. При первом открытии используется предпочтение браузера: региональные варианты `ru-RU` и `en-US` распознаются, при отсутствии подходящего перевода используется английский. Без языковых заголовков сервер сохраняет русский по умолчанию. Ручной выбор в меню сохраняется cookie `luch_locale` на год и имеет приоритет; изменение перезагружает страницу, включая серверные проверки прямых ссылок.

Язык интерфейса не меняет язык обучения, редакцию банка, ответы ученика или комментарии преподавателя. Причина блокировки показывается без перевода и как обычный текст. Статические подписи, формы, меню, сообщения, даты и страницы HTTP-ошибок используют общий каталог.

## Добавление перевода

1. Добавить код, собственное название и формат даты в `locales` в `packages/contracts/src/localization.ts`.
2. Создать каталог в `packages/contracts/src/locales` и подключить его в `localeCatalogs`. Ключи — исходные русские подписи, значения — перевод. Параметры `{0}`, `{1}` сохраняются.
3. Для новых интерфейсных подписей использовать `t()` из `apps/web/src/i18n`. Строки учебного банка и пользовательский ввод не передавать переводчику.
4. Добавить сценарий нового языка и проверку полноты его каталога в `scripts/check-locales.mjs`.

Переключатель строится из реестра языков. `npm run locale:check` проверяет покрытие текущих интерфейсных строк английским каталогом и параметры перевода; эта проверка также входит в `typecheck`. Новая библиотека или внешний переводческий API не нужны.
