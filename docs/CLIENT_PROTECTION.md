# Защита функций браузера

После обновления примените миграцию 028 через `npm run setup`. Настройки находятся в `/admin?tab=security` → «Защита функций браузера». Менять их может только суперадмин. Изменения сохраняются в PostgreSQL, проверяют актуальность редакции и отмечаются в журнале действий.

Оба переключателя **выключены по умолчанию**. Для каждого отдельно выбираются роли «Ученик», «Преподаватель», «Администратор»; начальный выбор — ученик и преподаватель. Снятие роли исключает её только из соответствующей защиты. Роль определяется действующей серверной сессией после входа. Анонимные посетители и гости встреч не получают роль ученика автоматически. Суперадмин исключён из обеих защит и сохраняет возможность изменить настройки.

## Правый клик и F12

«Ограничение правого клика и F12» ограничивает контекстное меню в основном содержимом страниц и перехватываемые страницей сочетания открытия DevTools, включая F12 и сочетания Chrome для Windows/Linux/macOS. Меню навигации, редактирование текста, ссылки, кнопки, обычное копирование и стандартные элементы управления медиа сохраняются. Защита не отключает клавиатуру, не останавливает браузер и не меняет учебные результаты.

Веб-страница не может полностью запретить инструменты разработчика Chrome, уже открытые DevTools или работу изменённого клиента. Это ограничение обычных действий в интерфейсе, а не граница доступа к данным. Права на учебные материалы и ответы по-прежнему проверяет сервер.

## Блокировщики

«Защита от блокировщиков» проверяет выполнение JavaScript, обмен необходимыми cookies, доступность проверочного скрипта и признаки скрытия проверочного элемента рекламными фильтрами. Проверка использует только ресурсы самой платформы и не собирает список установленных расширений. Кратковременный сбой проверяется повторно; после устранения причины можно нажать «Повторить проверку».

Пока действующего подтверждения нет, страницы и прикладной API выбранных ролей возвращают стандартный **HTTP 403**. Код прикладной ошибки — `CLIENT_CAPABILITIES_REQUIRED`. Отдельная страница отказа читается без JavaScript и объясняет, что нужно разрешить JavaScript, cookies и ресурсы платформы. После успешной проверки исходная страница открывается с прежними параметрами и сессией. Ссылки из писем и приглашений не расходуются проверкой. Открытый интерфейс перепроверяет настройки в фоне; повторная проверка не пересоздаёт уже открытые компоненты встречи.

Наличие любого расширения нельзя достоверно установить средствами сайта. Некоторые блокировщики допускают собственные ресурсы сайта и не выявляются; фильтры, сетевой сбой или изменённый клиент могут влиять на результат. Полное отключение cookies также делает невозможным обычный вход в аккаунт. Проверка не является криптографической аттестацией, блокировкой аккаунта или основанием менять оценки.

Ручной допуск старого браузера не отключает эти отдельные настройки. Чтобы отключить новый контроль для роли, снимите её в соответствующем списке. При необходимости оператор сервера может выполнить существующую команду `npm run security:reset`, отключающую ограничения доступа с сохранением списков и учебных данных; для PGlite сначала остановите API.

Основание для ограничений веб-среды: [открытие Chrome DevTools](https://developer.chrome.com/docs/devtools/open), [сочетания Chrome](https://developer.chrome.com/docs/devtools/shortcuts), [HTTP 403](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/403), [cookies](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Cookies).
