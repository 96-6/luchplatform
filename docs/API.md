# API платформы

API локально: `http://127.0.0.1:3000`. Клиент использует относительный `/api/v1`. Схемы ответов и технических записей находятся в `packages/contracts/src/index.ts`.

| Метод | Путь                   | Ответ                                                       | Доступ                         |
| ----- | ---------------------- | ----------------------------------------------------------- | ------------------------------ |
| GET   | `/api/v1/system`       | Название, этап, доступность dev tools                       | Общий                          |
| GET   | `/api/v1/health/live`  | `{ status: "ok" }`                                          | Общий                          |
| GET   | `/api/v1/health/ready` | 200, если база и миграции готовы; иначе 503                 | Общий                          |
| GET   | `/api/v1/dev/records`  | До 20 последних тестовых записей                            | Только `ENABLE_DEV_TOOLS=true` |
| POST  | `/api/v1/dev/records`  | Сохранённая тестовая запись; 201 для новой, 200 для повтора | Только `ENABLE_DEV_TOOLS=true` |

Тело POST:

```json
{
  "label": "Проверка сохранения",
  "operationId": "123e4567-e89b-42d3-a456-426614174000"
}
```

Текст обрезается по краям, должен содержать 1–120 символов. `operationId` — UUID операции, который клиент повторно использует, если ответ потерян. Повтор с изменённым текстом даёт 409; неизвестные поля отклоняются. Это технические записи, а не учебные ответы.

Успешный ответ:

```json
{
  "data": {
    "id": "123e4567-e89b-42d3-a456-426614174001",
    "operationId": "123e4567-e89b-42d3-a456-426614174000",
    "label": "Проверка сохранения",
    "createdAt": "2026-10-12T20:00:00.000Z"
  },
  "requestId": "123e4567-e89b-42d3-a456-426614174002"
}
```

Ошибка:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Проверьте введённые данные.",
    "requestId": "123e4567-e89b-42d3-a456-426614174002",
    "fields": { "label": ["Введите текст записи"] }
  }
}
```

| Код HTTP | Смысл                                                    |
| -------- | -------------------------------------------------------- |
| 400      | Некорректные поля или JSON                               |
| 403      | Запись из браузера с неразрешённым origin                |
| 404      | Неизвестный маршрут; в том числе отключённый dev API     |
| 409      | Один идентификатор операции использован с другим текстом |
| 413      | Превышен лимит тела запроса                              |
| 503      | База не готова либо сервис временно недоступен           |

`x-request-id` соответствует идентификатору в JSON. Ответы не кэшируются. Строка подключения и внешние ключи не входят ни в один ответ. Добавлены методы аккаунтов `/auth`, `/users`, `/teacher/students` и `/admin`. Кабинеты требуют соответствующей серверной роли. Настройка и пользовательский путь описаны в README; детальное описание защитных механизмов не публикуется.

## Учебный контент — задача 3

Все методы ниже требуют входа. Учебные материалы общие; пользовательские результаты этим API не выдаются. Общий конверт и ошибки остаются прежними.

| Метод | Путь под `/api/v1`                          | Результат                                                                    | Доступ       |
| ----- | ------------------------------------------- | ---------------------------------------------------------------------------- | ------------ |
| GET   | `/content/routes`                           | Текущие маршруты всех пакетов и число уроков                                 | Пользователь |
| GET   | `/content/packages/:packageId/routes/:id`   | Маршрут, упорядоченные уроки, навыки, наборы                                 | Пользователь |
| GET   | `/content/packages/:packageId/lessons/:id`  | Материал, медиа, навыки и задания выбранного режима                          | Пользователь |
| GET   | `/content/packages/:packageId/sets/:id`     | Отдельный набор и его упорядоченные задания                                  | Пользователь |
| GET   | `/admin/content/packages`                   | Список опубликованных пакетов                                                | Суперадмин   |
| POST  | `/admin/content/import`                     | Полный пакет `luch-content` в теле; состав и `imported`/`unchanged` в ответе | Суперадмин   |
| GET   | `/admin/content/packages/:packageId/export` | Полный JSON-пакет с решениями и метаданными                                  | Суперадмин   |

Для урока `purpose=practice|diagnostic|control`, по умолчанию `practice`. Для чтения конкретной редакции — `packageVersion=1`; без него читается текущая. В ссылках на уроки браузер закрепляет редакцию. Импорт требует текущего служебного токена из сессии, как остальные изменения кабинета.

Правильные варианты, допустимые текстовые ответы, объяснения, подсказки и рубрики исключены из DTO каталога. Отправка и проверка ответа выполняются через luch engine.

Лимит тела импорта — 2 МиБ. Некорректная структура/ссылки дают 400, конфликт версий — 409, неизвестный пакет/урок/редакция — 404. Импорт целиком откатывается при ошибке. Экспорт переносит JSON, файлы медиа нужно разместить отдельно. Подробности — [формат контента](CONTENT_FORMAT.md).

## luch engine — задача 4

Контракты находятся в `packages/contracts/src/engine.ts`. Все методы требуют действующей сессии; POST также требует CSRF-токен сессии. Владелец читает и изменяет свои прохождения. Преподаватель читает прохождения закреплённых учеников. Суперадмин имеет доступ ко всем прохождениям, включая управление от имени владельца и служебное представление.

| Метод | Путь под `/api/v1`        | Назначение                                                                                |
| ----- | ------------------------- | ----------------------------------------------------------------------------------------- |
| POST  | `/engine/runs`            | Начать или продолжить урок/набор из закреплённой редакции                                 |
| GET   | `/engine/runs`            | Список доступных прохождений с курсором; необязательный `userId`                          |
| GET   | `/engine/runs/:id`        | Текущий шаг, черновик, подсказки и попытки                                                |
| POST  | `/engine/runs/:id/save`   | Сохранить черновик с монотонной `revision`; `paused` останавливает учёт активного времени |
| POST  | `/engine/runs/:id/resume` | Возобновить текущий вопрос                                                                |
| POST  | `/engine/runs/:id/hint`   | Получить и записать использование очередной подсказки в тренировке                        |
| POST  | `/engine/runs/:id/answer` | Проверить ответ и атомарно сохранить попытку                                              |
| POST  | `/engine/runs/:id/next`   | Перейти после ответа; завершить последнее задание                                         |
| POST  | `/engine/runs/:id/retry`  | Открыть новую попытку текущего тренировочного задания                                     |

Начало:

```json
{
  "packageId": "luch-demo",
  "packageVersion": 1,
  "source": { "type": "lesson", "id": "rki-01", "purpose": "practice" }
}
```

Вместо урока можно передать `{ "type": "set", "id": "rki-practice" }`; режим берётся из набора. Без `packageVersion` новый запуск выбирает текущую редакцию, а дальнейшие запросы используют закреплённую версию прохождения. `restart=true` создаёт новый цикл после завершения; обычный повтор возвращает сохранённое прохождение. Только суперадмин может передать чужой `userId` при создании.

Отправка ответа:

```json
{
  "turnId": "123e4567-e89b-42d3-a456-426614174001",
  "operationId": "123e4567-e89b-42d3-a456-426614174002",
  "answer": { "type": "short_text", "text": "зовут" }
}
```

Для выбора используется `{ "type": "choice", "optionId": "option-1" }` с реальным ID варианта текущего задания. Ответ содержит `{ attempt, view }` внутри общего конверта. Повтор того же ключа и ответа возвращает прежнюю попытку; изменённый ответ под тем же ключом, конфликт черновика или устаревший шаг дают 409. Неизвестный вариант и неверный тип ответа дают 400 без создания попытки.

`save` получает `{ turnId, revision, draftAnswer, paused }`. `resume`, `next`, `retry` получают `{ turnId }`; `hint` — `{ turnId, index }`. Чтение не изменяет черновик и не возобновляет время. `GET /engine/runs` принимает `limit` от 1 до 100 и пару `beforeCreatedAt`/`beforeId` из `nextCursor`.

Оценка и объяснение выдаются ученику после ответа в тренировке, после завершения всего прохождения в диагностике и контроле. Ученический ответ не содержит ключей будущих заданий. Суперадмин получает служебные данные, преподаватель — результаты своих учеников. Чужое недоступное прохождение возвращает 404; запрещённое действие преподавателя — 403. В попытке сохраняются исходный ответ, автор, помощь, предыдущая обратная связь, время и версии проверки.

Фоновая проверка использует `/engine/runs/:id/integrity`; настройка `/admin/engine/integrity-policy` доступна только суперадмину (GET/POST). Контекст доступен уполномоченным проверяющим и не изменяет учебный балл. Настройка описана в README; внутренние правила проверки здесь не приводятся.

## Анкета и диагностика — задача 5

Схемы — `packages/contracts/src/diagnostics.ts`. Сессия обязательна; POST требует CSRF. По умолчанию работа идёт с собственным профилем ученика, параметр `userId` выбирает доступного ученика. Преподаватель читает только закреплённых учеников и не изменяет их данные; суперадмин имеет полный доступ.

| Метод | Путь под `/api/v1`  | Результат                                                          |
| ----- | ------------------- | ------------------------------------------------------------------ |
| GET   | `/learning/profile` | Пользователь, сохранённая анкета или `null`, возможность изменения |
| POST  | `/learning/profile` | Проверка и сохранение редакции анкеты                              |
| POST  | `/diagnostics`      | Начать/продолжить набор выбранного в анкете языка                  |
| GET   | `/diagnostics`      | История диагностик доступного ученика с курсором                   |
| GET   | `/diagnostics/:id`  | Снимок анкеты, состояние и сохранённый итог либо `result=null`     |

Сохранение анкеты:

```json
{
  "language": "en",
  "goal": "work",
  "experience": "some",
  "minutesPerDay": 20,
  "revision": 0
}
```

Для первой анкеты `revision=0`, для изменения — текущая редакция. `language=ru|en`, `goal=daily_life|travel|work|study`, `experience=none|some|regular`, минуты — целое число 5–120. Повтор содержимого не создаёт новую редакцию; устаревшее изменение даёт 409. Сервер хранит автора и снимки редакций.

Начало диагностики: `{ "profileRevision": 1, "restart": false }`, при необходимости с доступным `userId`. Без сохранённой анкеты или с устаревшей редакцией — 409. Ответ содержит `{ diagnostic, result, writable }`; `diagnostic.runId` открывается общим API `/engine/runs/:id`. `restart=true` после завершения создаёт новый цикл. Пока есть активная диагностика этого языка, она продолжается по своему исходному снимку.

История принимает `limit` 1–100 и пару `beforeCreatedAt`/`beforeId` из `nextCursor`. Текущий вопрос, ответы и черновик обслуживает luch engine. В его сводке `diagnosticId` указывает на связанный итог либо равен `null` для самостоятельного урока/набора.

После завершения результат содержит `preliminary=true`, дату/версию расчёта, отдельные навыки, самостоятельные и выполненные с помощью успешные ответы, сильные стороны и затруднения. Итог сохраняется сервером атомарно с завершением; метода отправки результата с клиента нет. Недоступные чужие данные возвращают 404.

Создание готовых аккаунтов и управление Authenticator доступны через кабинет суперадмина. Операции изменения требуют его сессию и CSRF. Настройка и пользовательский путь описаны в README; значения локального доступа и внутренние защитные правила не публикуются.

## Первоначальный план — задача 6

Контракты находятся в `packages/contracts/src/plans.ts`. Все методы требуют сессии, POST — CSRF. Ученик читает и запускает собственные назначения, преподаватель читает закреплённых учеников, суперадмин видит и запускает любые назначения с записью автора.

| Метод | Путь под `/api/v1`                           | Результат                                                                                            |
| ----- | -------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| GET   | `/plans`                                     | История планов владельца или доступного `userId`; фильтр языка, курсор и `limit` 1–100               |
| POST  | `/plans`                                     | `{ diagnosticId }`: сформировать план по завершённой диагностике либо вернуть существующий           |
| GET   | `/plans/:id`                                 | `{ plan, assignments, nextAssignmentId, writable, manageable }`: порядок, причины и реальные статусы |
| POST  | `/plans/:id/assignments/:assignmentId/start` | Тело `{}`; создать или продолжить связанный run, вернуть обычный `RunView` luch engine               |

План содержит ID исходной диагностики, анкету/редакцию, закреплённый пакет и маршрут, версию правил, автора/дату, число завершённых уроков и рекомендуемых дней. Назначение содержит урок, порядок, день, длительность, сохранённую причину, точные ссылки на упражнения, run, автора/дату запуска и статус `pending|active|completed`. Ответ не содержит решений упражнений.

`nextCursor` списка содержит `createdAt` и `id`; оба передаются как `beforeCreatedAt`/`beforeId` вместе. Без `userId` используется текущий пользователь; роль преподавателя/суперадмина требует выбора ученика. Список и чтение ничего не формируют.

Новые диагностики сохраняют план автоматически в транзакции завершения. `DiagnosticView.planId` — ссылка либо `null` для активной/старой диагностики или маршрута без тренировочного банка. `RunSummary.planIds` — связанные планы для перехода из упражнения. Один план соответствует одной диагностике; повтор формирования/начала не создаёт дубликат. Новая диагностика создаёт отдельный план; завершённое назначение не сбрасывается повтором запуска.

Незавершённая диагностика даёт 409 `DIAGNOSTIC_INCOMPLETE`; отсутствие тренировочного банка — 409 `PLAN_CONTENT_UNAVAILABLE`. Недоступные чужие данные/неизвестное назначение — 404, запрещённое изменение преподавателем — 403. Клиент не передаёт статус выполнения, оценки, причины или порядок. Правила — [PLANS.md](PLANS.md).

## Адаптация — задача 7

| Метод | Путь под `/api/v1`          | Результат                                                                      |
| ----- | --------------------------- | ------------------------------------------------------------------------------ |
| GET   | `/learning/skills?userId=…` | Сохранённые состояния навыков доступного ученика                               |
| GET   | `/plans/:id/history`        | Датированные изменения: причины, навык, результат, назначение, попытка и автор |

Доступ: ученик — свои данные, преподаватель — закреплённые ученики, суперадмин — все ученики. История принимает `limit` 1–100 и пару `beforeCreatedAt`/`beforeId` из `nextCursor`; курсорные страницы не дублируют записи. Текущая роль `admin` не предоставляет общего доступа к учебным данным.

Состояние навыка закреплено владельцем, пакетом/версией и навыком. Ответ включает число попыток, ошибок, самостоятельных успехов, успехов с подсказкой и другой помощью, диагностических/контрольных наблюдений, серию и даты последних результатов. Учебная оценка демонстрационная.

В `PlanAssignment` добавлены `kind=initial|correction|supported_practice|review`, `purpose`, `dueAt`, `canStart`. Точные ссылки упражнений содержат необязательный `generatedExerciseId`. Назначение до срока даёт 409 `ASSIGNMENT_NOT_DUE`; суперадмин может открыть его для отладки, с отметкой помощи. `nextAssignmentId` выбирает активное или готовое назначение, пропуская будущие проверки.

Адаптивное назначение запускается существующим POST `/plans/:id/assignments/:assignmentId/start`; публичный `/engine/runs` не принимает произвольный ID назначения. Run получает `sourceType=assignment` и выполняет одно закреплённое упражнение. `current.generatedExerciseId` и `Attempt.generatedExerciseId` отличают сгенерированный вариант от исходного задания. Проверка ответа и продолжение используют прежние API luch engine.

## ИИ, расходы и listening

| Метод | Путь под `/api/v1`                                   | Доступ и результат                                                                                 |
| ----- | ---------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| GET   | `/admin/providers`                                   | Администратор/суперадмин: настройки, состояние ключей, расходы                                     |
| POST  | `/admin/providers/controls`                          | Администратор/суперадмин: `{ revision, controls }`, рабочие параметры в пределах общих ограничений |
| POST  | `/admin/providers/ceilings`                          | Суперадмин: `{ revision, ceilings }`, общие ограничения                                            |
| POST  | `/admin/providers/:provider`                         | Суперадмин: модель, голоса, цены, ключ и включение одного провайдера                               |
| GET   | `/admin/providers/requests`                          | Администратор/суперадмин: последние 100 платных запросов и учётные суммы                           |
| POST  | `/engine/runs/:id/steps/:stepId/listening`           | Владелец/суперадмин: `{ operationId }`, подготовить или вернуть кэш `{ url, cached }`              |
| GET   | `/engine/runs/:id/steps/:stepId/listening/:cacheKey` | Владелец/его преподаватель/суперадмин: сохранённое аудио, `audio/mpeg`, поддержка Range            |

POST требуют сессии, допустимого origin и CSRF. Обычные ученик/преподаватель не управляют настройками. `provider=openai|neuroapi|elevenlabs|elevenlabs_stt|heygen`. Все денежные поля — целые микродоллары; входные/выходные цены за миллион токенов, цена TTS за тысячу символов, STT/видео за минуту. Полные контракты — `packages/contracts/src/providers.ts`.

Общие ограничения: суммы за всё время, день, месяц и на ученика; число вызовов на ученика в день, максимальные токены, символы речи, одновременные вызовы и срок подтверждения цен. Рабочие настройки: переключатели генерации/listening/аудиовариантов, `strategy=cheapest|openai|neuroapi`, текущие ограничения и `reviewDelayHours`. Редакции настроек защищают от потерянного обновления; устаревшая редакция даёт 409 `SETTINGS_CHANGED`, превышение разрешённых ограничений — 400 `LIMIT_EXCEEDED`.

Обновление провайдера содержит `revision`, `enabled`, `model`, `voiceRu`, `voiceEn`, `inputRate`, `outputRate`, `characterRate`, `confirmPricing`; необязательный `apiKey` заменяет ключ, `clearKey` удаляет. Ответ содержит только `keyConfigured` и `keySource`; значения ключа не возвращаются. Ненужные данному провайдеру цены передаются как `null`.

В ExerciseView добавлен `hasListening`; закрытый текст записи не выдаётся. `current.listeningUrl` — сохранённая ссылка либо `null` до подготовки. `decision=comment|confirm|correct`. Комментарий обязателен, trim 1–3000 символов. `correct` передаётся только для `correct`; подтверждение использует текущую оценку. `revision` — `attempt.reviewRevision`, изначально 0. Неизменённая оценка требует решения `confirm`. Каждый комментарий увеличивает редакцию. История проверок возвращается по 20 записей, от новых к старым; следующая страница — `beforeRevision=nextReviewCursor.revision`. `solution` доступно только проверяющему после открытия оценки, иначе `null`. Диагностика и контроль допускают проверку только после завершения набора.

`Attempt.evaluation.source=teacher` означает последнее подтверждение/исправление; `automaticEvaluation` хранит исходный результат luch engine. `teacherReview` содержит соответствующее решение с автором и временем, `reviewRevision` учитывает также комментарии. Комментарий не сбрасывает прежнюю оценку. Исходный ответ и сведения о помощи неизменны. Главная и прогресс используют текущую оценку: `progress.teacherReviewedAttempts`, `recentResults.teacherReviewed`. Первоначальный результат диагностики и причины плана остаются сохранённым снимком; `diagnostic.teacherReviewedAttempts` отмечает последующие проверки.

Для назначения `dueAt` — ISO UTC или `null` (доступно сразу); `estimatedMinutes` 1–60, по умолчанию 3. Создаётся `kind=teacher` с точным упражнением исходного банка и причиной `kind=teacher`. Запуск использует прежний метод `/plans/:id/assignments/:assignmentId/start` и общий luch engine, без генерации варианта. `action=reschedule|cancel`; `revision` берётся из назначения. Менять можно только ещё не начатые и не отменённые назначения. Перенос/отмена сохраняют первоначальную причину, текущую `teacherNote` и историю с автором. При отмене `dueAt` не изменяется.

`PlanView.manageable` разрешает интерфейс преподавателя; `writable` по-прежнему относится к прохождению учеником/суперадмином. У назначения добавлены `revision`, `teacherNote`, `cancelledAt`, статус `cancelled`. Отмена запрещает запуск, исключается из `totalAssignments`, заданий на сегодня и знаменателя выполнения; `cancelledAssignments` считается отдельно. `totalAssignments=0` означает отсутствие активных назначений. История плана допускает `attemptId=null`, `outcome=null` для действий без ответа; `createdByName` показывает автора. Новые действия — `assessment_reviewed`, `teacher_assignment_added`, `teacher_assignment_rescheduled`, `teacher_assignment_cancelled`.

UUID операции сохраняется вместе с точным запросом. Повтор возвращает актуальное состояние без нового действия; изменённое содержимое с тем же UUID даёт 409 `TEACHER_OPERATION_CONFLICT`. Устаревшие редакции — `REVIEW_CHANGED`/`ASSIGNMENT_CHANGED`; начатое или отменённое назначение — `ASSIGNMENT_LOCKED`; запуск отменённого — `ASSIGNMENT_CANCELLED`. Незавершённый закрытый набор — `ASSESSMENT_INCOMPLETE`, упражнение вне закреплённого банка — `INVALID_TEACHER_EXERCISE`. Авторство, оценка/назначение, проекция навыка и история сохраняются транзакционно. Повторная отправка и одновременное действие ученика не создают дубликаты.

Метки являются сообщением клиента, не аттестацией оборудования.

Итог после завершения: комментарий 1–3000; `homework[]` до 50 строк `{ studentId, planId, exerciseId, reason, dueAt }`. План принадлежит участнику и языку встречи; действуют прежние проверки доступа преподавателя. Все назначения используют существующий банк и luch engine. Повтор UUID безопасен, другой запрос с прежним UUID — `MEETING_OPERATION_CONFLICT`; устаревшие редакции — `MEETING_CHANGED` / `MEETING_SUMMARY_CHANGED`. `MEETING_NOT_ADMITTED`, `MEETING_REMOVED`, `MEETING_NOT_OPEN`, `MEETING_CLOSED` описывают состояние входа. `VIDEO_NOT_CONFIGURED` / `VIDEO_UNAVAILABLE` — технические состояния без изменения оценок. Чат ограничен 20 новыми сообщениями в минуту; история принимает пару `beforeCreatedAt`/`beforeId`.

Браузерный `serverUrl` указывает на `/api/v1/video` приложения. WebSocket `/video/rtc` и `/video/rtc/v1` и их GET `/validate` требуют действующую сессию, собственный подписанный допуск и текущее разрешение подключения. Старый допуск удалённого/вышедшего участника не даёт повторного входа. Порт сигнализации SFU — внутренний.

Настройка и ограничения — [MEETINGS.md](MEETINGS.md).

## Прогресс и учебный отчёт (задача 13)

Все пути ниже имеют префикс `/api/v1`. Доступ: ученик к себе, преподаватель к закреплённому ученику, суперадмин ко всем ученикам. Роль администратора операций этот доступ не получает. Смена закрепления проверяется при каждом запросе.

| Метод | Путь                                 | Результат                                                                           |
| ----- | ------------------------------------ | ----------------------------------------------------------------------------------- |
| GET   | `/reports/me?language=ru`            | Собственный отчёт ученика; язык по текущей анкете, при её отсутствии — РКИ          |
| GET   | `/reports/:id?language=ru`           | `{ report, reviewer, refreshedAt }`, общий отчёт и приватная часть проверяющего     |
| GET   | `/reports/:id/attempts?language=ru`  | Страница попыток с текущей/исходной оценкой, помощью и последним оценочным решением |
| GET   | `/reports/:id/changes?language=ru`   | Страница сохранённых изменений всех планов выбранного языка                         |
| GET   | `/reports/:id/integrity?language=ru` | Только проверяющему: страница сохранённых наблюдений и их вкладов                   |

`language=ru|en`. Для страниц язык обязателен; поддерживаются `limit` 1–50 (по умолчанию 20), пара `beforeCreatedAt`/`beforeId`. `nextCursor` содержит `{ createdAt, id }` либо `null`. Общие показатели считаются по всей истории, независимо от размера страницы.

`report` содержит `revision`, пользователя/язык/сохранённую анкету, дату последнего учебного действия, `counts`, `completion`, `byPurpose`, `skills`, `repeatedErrors`, `planChangesCount`, первую страницу `planChanges`/`recentAttempts`, диагностику и `next` с текущим прохождением/планом/существующими назначениями. Самостоятельность и помощь берутся из исходной попытки. Текущая оценка — `COALESCE(teacher_correct,is_correct)`; комментарии не заменяют оценочное решение. Подтверждение преподавателя пересекается с категориями помощи/самостоятельности.

Для незавершённого закрытого набора оценки и самостоятельность мини-карточки равны `null`; оценочные агрегаты, повторные ошибки и приватные веса такой попытки ещё не вычисляются. После завершения результаты появляются из существующего движка.

У ученика `reviewer=null`. Приватная часть содержит версию/параметры условных весов, покрытие данными, исходное число самостоятельных успехов, `weightedEvidenceUnits`, разницу `evidenceReductionUnits`, вклады видов наблюдений, разбивку по навыкам и страницу контекста. Это дополнительный показатель свидетельств для ручной проверки; он не меняет оценки/навыки/план. Отсутствующим/неизвестным данным не присваивается штраф. Попытка получить приватную страницу учеником даёт `REPORT_REVIEWER_REQUIRED` (403); чужой отчёт не раскрывается.

Чтение согласовано одной транзакцией `REPEATABLE READ READ ONLY`, `refreshedAt` находится вне общего объекта, приватная часть не входит в его `revision`. Прочтение не создаёт попыток/назначений. При служебном просмотре суперадмина отдельно сохраняется аудит. Правила — [REPORTS.md](REPORTS.md).

## Интерфейсы и обслуживание

- `GET /navigation/access?path=ENCODED_LOCAL_PATH` — проверка известной страницы, параметров, роли, владельца, ресурса и временных условий; возвращает `{path}` без учебных данных. Не выдаёт права для другого API. Применяется также перед HTML, включая Vite.
- `GET /operations` — администратор/суперадмин: состояние базы, версия схемы, агрегаты очередей/подключений, доступные действия и последние 20 операций; без ключей, адресов базы и ответов.
- `POST /operations/actions` — CSRF и роль; `{operationId,kind}`. Виды: `recover_learning`, `retry_video`; только суперадмин — `seed_content`, `expire_audio`. Результат: `{id,kind,status,actorName,createdAt,completedAt,result}`. Завершённый повтор возвращает прежний результат; конфликт вида/выполняющаяся операция — 409. Техническая ошибка сохраняется как `status=failed` в результате операции.
- `POST /admin/teacher-students/remove` — суперадмин/CSRF, `{teacherId,studentId}`; повторяемое снятие закрепления с журналом, без удаления учебных данных.

Защищённые HTML-переходы возвращают 400/401/403/404/410 по условию, неизвестные страницы/файлы не получают успешную оболочку SPA. Правила и границы — [INTERFACES_ACCESS.md](INTERFACES_ACCESS.md).

## Дополнение: локализация и статусы аккаунта

`User` содержит `isActive`, `isBlocked` и `blockReason`. `POST /admin/accounts/:id` принимает `isActive`, `isBlocked`, `blockReason` (до 1000 символов) и `accessVerified`; доступен только суперадмину с CSRF. Снятие бана очищает причину. Старые клиенты могут не передавать новые поля: это не активирует деактивированный аккаунт и не удаляет сохранённую причину действующего бана. Деактивация/бан отзывают сессии; собственный доступ отключить нельзя. При правильном коде входа ограниченный аккаунт получает 403 с `ACCOUNT_DEACTIVATED` либо `ACCOUNT_BLOCKED`; причина передаётся отдельной строкой сообщения. Причины доступны в управлении аккаунтом суперадмину и в отказе при корректном входе; профиль ученика у преподавателя их не раскрывает. Неправильные учётные данные сохраняют общий 401.

Серверные страницы ошибок учитывают `luch_locale` и `Accept-Language`, сохраняя статус 400/401/403/404/410/503. Язык интерфейса не является параметром учебного банка или разрешений.
