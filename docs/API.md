# API платформы

API локально: `http://127.0.0.1:3000`. Клиент использует относительный `/api/v1`. Схемы ответов и технических записей находятся в `packages/contracts/src/index.ts`.

| Метод | Путь                   | Ответ                                                       | Доступ                         |
| ----- | ---------------------- | ----------------------------------------------------------- | ------------------------------ |
| GET   | `/api/v1/system`       | Название, этап, доступность dev tools                       | Общий                          |
| GET   | `/api/v1/health/live`  | `{ status: "ok" }`                                          | Общий                          |
| GET   | `/api/v1/health/ready` | 200, если база и миграции готовы; иначе 503                 | Общий                          |
| GET   | `/api/v1/dev/records`  | До 20 последних тестовых записей                            | Только `ENABLE_DEV_TOOLS=true` |
| POST  | `/api/v1/dev/records`  | Сохранённая тестовая запись; 201 для новой, 200 для повтора | Только `ENABLE_DEV_TOOLS=true` |

Тело POST:

```json
{
  "label": "Проверка сохранения",
  "operationId": "123e4567-e89b-42d3-a456-426614174000"
}
```

Текст обрезается по краям, должен содержать 1–120 символов. `operationId` — UUID операции, который клиент повторно использует, если ответ потерян. Повтор с изменённым текстом даёт 409; неизвестные поля отклоняются. Это технические записи, а не учебные ответы.

Успешный ответ:

```json
{
  "data": {
    "id": "123e4567-e89b-42d3-a456-426614174001",
    "operationId": "123e4567-e89b-42d3-a456-426614174000",
    "label": "Проверка сохранения",
    "createdAt": "2026-10-12T20:00:00.000Z"
  },
  "requestId": "123e4567-e89b-42d3-a456-426614174002"
}
```

Ошибка:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Проверьте введённые данные.",
    "requestId": "123e4567-e89b-42d3-a456-426614174002",
    "fields": { "label": ["Введите текст записи"] }
  }
}
```

| Код HTTP | Смысл                                                    |
| -------- | -------------------------------------------------------- |
| 400      | Некорректные поля или JSON                               |
| 403      | Запись из браузера с неразрешённым origin                |
| 404      | Неизвестный маршрут; в том числе отключённый dev API     |
| 409      | Один идентификатор операции использован с другим текстом |
| 413      | Превышен лимит тела запроса                              |
| 503      | База не готова либо сервис временно недоступен           |

`x-request-id` соответствует идентификатору в JSON. Ответы не кэшируются. Строка подключения и внешние ключи не входят ни в один ответ. Добавлены методы аккаунтов `/auth`, `/users`, `/teacher/students` и `/admin`. Кабинеты требуют соответствующей серверной роли. Настройка и пользовательский путь описаны в README; детальное описание защитных механизмов не публикуется.

## Учебный контент — задача 3

Все методы ниже требуют входа. Учебные материалы общие; пользовательские результаты этим API не выдаются. Общий конверт и ошибки остаются прежними.

| Метод | Путь под `/api/v1`                          | Результат                                                                    | Доступ       |
| ----- | ------------------------------------------- | ---------------------------------------------------------------------------- | ------------ |
| GET   | `/content/routes`                           | Текущие маршруты всех пакетов и число уроков                                 | Пользователь |
| GET   | `/content/packages/:packageId/routes/:id`   | Маршрут, упорядоченные уроки, навыки, наборы                                 | Пользователь |
| GET   | `/content/packages/:packageId/lessons/:id`  | Материал, медиа, навыки и задания выбранного режима                          | Пользователь |
| GET   | `/content/packages/:packageId/sets/:id`     | Отдельный набор и его упорядоченные задания                                  | Пользователь |
| GET   | `/admin/content/packages`                   | Список опубликованных пакетов                                                | Суперадмин   |
| POST  | `/admin/content/import`                     | Полный пакет `luch-content` в теле; состав и `imported`/`unchanged` в ответе | Суперадмин   |
| GET   | `/admin/content/packages/:packageId/export` | Полный JSON-пакет с решениями и метаданными                                  | Суперадмин   |

Для урока `purpose=practice|diagnostic|control`, по умолчанию `practice`. Для чтения конкретной редакции — `packageVersion=1`; без него читается текущая. В ссылках на уроки браузер закрепляет редакцию. Импорт требует текущего служебного токена из сессии, как остальные изменения кабинета.

Правильные варианты, допустимые текстовые ответы, объяснения, подсказки и рубрики исключены из DTO каталога. Отправка и проверка ответа выполняются через luch engine.

Лимит тела импорта — 2 МиБ. Некорректная структура/ссылки дают 400, конфликт версий — 409, неизвестный пакет/урок/редакция — 404. Импорт целиком откатывается при ошибке. Экспорт переносит JSON, файлы медиа нужно разместить отдельно. Подробности — [формат контента](CONTENT_FORMAT.md).

## luch engine — задача 4

Контракты находятся в `packages/contracts/src/engine.ts`. Все методы требуют действующей сессии; POST также требует CSRF-токен сессии. Владелец читает и изменяет свои прохождения. Преподаватель читает прохождения закреплённых учеников. Суперадмин имеет доступ ко всем прохождениям, включая управление от имени владельца и служебное представление.

| Метод | Путь под `/api/v1`        | Назначение                                                                                |
| ----- | ------------------------- | ----------------------------------------------------------------------------------------- |
| POST  | `/engine/runs`            | Начать или продолжить урок/набор из закреплённой редакции                                 |
| GET   | `/engine/runs`            | Список доступных прохождений с курсором; необязательный `userId`                          |
| GET   | `/engine/runs/:id`        | Текущий шаг, черновик, подсказки и попытки                                                |
| POST  | `/engine/runs/:id/save`   | Сохранить черновик с монотонной `revision`; `paused` останавливает учёт активного времени |
| POST  | `/engine/runs/:id/resume` | Возобновить текущий вопрос                                                                |
| POST  | `/engine/runs/:id/hint`   | Получить и записать использование очередной подсказки в тренировке                        |
| POST  | `/engine/runs/:id/answer` | Проверить ответ и атомарно сохранить попытку                                              |
| POST  | `/engine/runs/:id/next`   | Перейти после ответа; завершить последнее задание                                         |
| POST  | `/engine/runs/:id/retry`  | Открыть новую попытку текущего тренировочного задания                                     |

Начало:

```json
{
  "packageId": "luch-demo",
  "packageVersion": 1,
  "source": { "type": "lesson", "id": "rki-01", "purpose": "practice" }
}
```

Вместо урока можно передать `{ "type": "set", "id": "rki-practice" }`; режим берётся из набора. Без `packageVersion` новый запуск выбирает текущую редакцию, а дальнейшие запросы используют закреплённую версию прохождения. `restart=true` создаёт новый цикл после завершения; обычный повтор возвращает сохранённое прохождение. Только суперадмин может передать чужой `userId` при создании.

Отправка ответа:

```json
{
  "turnId": "123e4567-e89b-42d3-a456-426614174001",
  "operationId": "123e4567-e89b-42d3-a456-426614174002",
  "answer": { "type": "short_text", "text": "зовут" }
}
```

Для выбора используется `{ "type": "choice", "optionId": "option-1" }` с реальным ID варианта текущего задания. Ответ содержит `{ attempt, view }` внутри общего конверта. Повтор того же ключа и ответа возвращает прежнюю попытку; изменённый ответ под тем же ключом, конфликт черновика или устаревший шаг дают 409. Неизвестный вариант и неверный тип ответа дают 400 без создания попытки.

`save` получает `{ turnId, revision, draftAnswer, paused }`. `resume`, `next`, `retry` получают `{ turnId }`; `hint` — `{ turnId, index }`. Чтение не изменяет черновик и не возобновляет время. `GET /engine/runs` принимает `limit` от 1 до 100 и пару `beforeCreatedAt`/`beforeId` из `nextCursor`.

Оценка и объяснение выдаются ученику после ответа в тренировке, после завершения всего прохождения в диагностике и контроле. Ученический ответ не содержит ключей будущих заданий. Суперадмин получает служебные данные, преподаватель — результаты своих учеников. Чужое недоступное прохождение возвращает 404; запрещённое действие преподавателя — 403. В попытке сохраняются исходный ответ, автор, помощь, предыдущая обратная связь, время и версии проверки.

Фоновая проверка использует `/engine/runs/:id/integrity`; настройка `/admin/engine/integrity-policy` доступна только суперадмину (GET/POST). Контекст доступен уполномоченным проверяющим и не изменяет учебный балл. Настройка описана в README; внутренние правила проверки здесь не приводятся.

## Анкета и диагностика — задача 5

Схемы — `packages/contracts/src/diagnostics.ts`. Сессия обязательна; POST требует CSRF. По умолчанию работа идёт с собственным профилем ученика, параметр `userId` выбирает доступного ученика. Преподаватель читает только закреплённых учеников и не изменяет их данные; суперадмин имеет полный доступ.

| Метод | Путь под `/api/v1`  | Результат                                                          |
| ----- | ------------------- | ------------------------------------------------------------------ |
| GET   | `/learning/profile` | Пользователь, сохранённая анкета или `null`, возможность изменения |
| POST  | `/learning/profile` | Проверка и сохранение редакции анкеты                              |
| POST  | `/diagnostics`      | Начать/продолжить набор выбранного в анкете языка                  |
| GET   | `/diagnostics`      | История диагностик доступного ученика с курсором                   |
| GET   | `/diagnostics/:id`  | Снимок анкеты, состояние и сохранённый итог либо `result=null`     |

Сохранение анкеты:

```json
{
  "language": "en",
  "goal": "work",
  "experience": "some",
  "minutesPerDay": 20,
  "revision": 0
}
```

Для первой анкеты `revision=0`, для изменения — текущая редакция. `language=ru|en`, `goal=daily_life|travel|work|study`, `experience=none|some|regular`, минуты — целое число 5–120. Повтор содержимого не создаёт новую редакцию; устаревшее изменение даёт 409. Сервер хранит автора и снимки редакций.

Начало диагностики: `{ "profileRevision": 1, "restart": false }`, при необходимости с доступным `userId`. Без сохранённой анкеты или с устаревшей редакцией — 409. Ответ содержит `{ diagnostic, result, writable }`; `diagnostic.runId` открывается общим API `/engine/runs/:id`. `restart=true` после завершения создаёт новый цикл. Пока есть активная диагностика этого языка, она продолжается по своему исходному снимку.

История принимает `limit` 1–100 и пару `beforeCreatedAt`/`beforeId` из `nextCursor`. Текущий вопрос, ответы и черновик обслуживает luch engine. В его сводке `diagnosticId` указывает на связанный итог либо равен `null` для самостоятельного урока/набора.

После завершения результат содержит `preliminary=true`, дату/версию расчёта, отдельные навыки, самостоятельные и выполненные с помощью успешные ответы, сильные стороны и затруднения. Итог сохраняется сервером атомарно с завершением; метода отправки результата с клиента нет. Недоступные чужие данные возвращают 404.

Создание готовых аккаунтов и управление Authenticator доступны через кабинет суперадмина. Операции изменения требуют его сессию и CSRF. Настройка и пользовательский путь описаны в README; значения локального доступа и внутренние защитные правила не публикуются.

## Первоначальный план — задача 6

Контракты находятся в `packages/contracts/src/plans.ts`. Все методы требуют сессии, POST — CSRF. Ученик читает и запускает собственные назначения, преподаватель читает закреплённых учеников, суперадмин видит и запускает любые назначения с записью автора.

| Метод | Путь под `/api/v1`                           | Результат                                                                                  |
| ----- | -------------------------------------------- | ------------------------------------------------------------------------------------------ |
| GET   | `/plans`                                     | История планов владельца или доступного `userId`; фильтр `language=ru                      | en`, курсор и `limit` 1–100 |
| POST  | `/plans`                                     | `{ diagnosticId }`: сформировать план по завершённой диагностике либо вернуть существующий |
| GET   | `/plans/:id`                                 | `{ plan, assignments, nextAssignmentId, writable }`: порядок, причины и реальные статусы   |
| POST  | `/plans/:id/assignments/:assignmentId/start` | Тело `{}`; создать или продолжить связанный run, вернуть обычный `RunView` luch engine     |

План содержит ID исходной диагностики, анкету/редакцию, закреплённый пакет и маршрут, версию правил, автора/дату, число завершённых уроков и рекомендуемых дней. Назначение содержит урок, порядок, день, длительность, сохранённую причину, точные ссылки на упражнения, run, автора/дату запуска и статус `pending|active|completed`. Ответ не содержит решений упражнений.

`nextCursor` списка содержит `createdAt` и `id`; оба передаются как `beforeCreatedAt`/`beforeId` вместе. Без `userId` используется текущий пользователь; роль преподавателя/суперадмина требует выбора ученика. Список и чтение ничего не формируют.

Новые диагностики сохраняют план автоматически в транзакции завершения. `DiagnosticView.planId` — ссылка либо `null` для активной/старой диагностики или маршрута без тренировочного банка. `RunSummary.planIds` — связанные планы для перехода из упражнения. Один план соответствует одной диагностике; повтор формирования/начала не создаёт дубликат. Новая диагностика создаёт отдельный план; завершённое назначение не сбрасывается повтором запуска.

Незавершённая диагностика даёт 409 `DIAGNOSTIC_INCOMPLETE`; отсутствие тренировочного банка — 409 `PLAN_CONTENT_UNAVAILABLE`. Недоступные чужие данные/неизвестное назначение — 404, запрещённое изменение преподавателем — 403. Клиент не передаёт статус выполнения, оценки, причины или порядок. Правила — [PLANS.md](PLANS.md).
