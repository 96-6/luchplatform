# Защита браузеров

Суперадмин открывает `/admin?tab=security` → «Безопасность браузеров». Настройки сохраняются отдельной кнопкой. Изменения требуют текущей сессии суперадмина, CSRF и актуальной редакции, попадают в журнал действий. Новые правила применяются при следующем запросе; открытый интерфейс также обновляет проверку в фоне. Изменение не является блокировкой аккаунта и не меняет учебные результаты.

## Два режима

**«Защита от устаревших браузеров» по умолчанию включена.** Она запрещает выбранные семейства браузеров, версии ниже настроенного минимума и несовместимые возможности. По умолчанию ограничены Internet Explorer, Edge Legacy, Opera Mini, UC Browser, Puffin, QQ Browser и WebView. Это редактируемая политика совместимости, а не утверждение о небезопасности всех выпусков этих продуктов.

Актуальный Яндекс Браузер допускается. После первого входа пользователь видит «Ваш браузер может быть несовместим с платформой». Кнопка «Понятно» сохраняет подтверждение для аккаунта и семейства браузера; обновление страницы и следующий вход его не сбрасывают. Для гостя подтверждение сохраняется в текущем браузере, без создания обычного аккаунта.

**«Усиленная защита» по умолчанию выключена.** Она допускает только распознанные семейства из разрешённого списка и требует действующую проверку браузера для API. По умолчанию разрешены Chrome, Chromium, Opera, Vanadium, Edge, Firefox, Safari, Brave, Vivaldi, Samsung Internet и DuckDuckGo. Яндекс Браузер запрещён всегда, в том числе для суперадмина; добавить его в список разрешённых нельзя. При отказе показывается «Ваш браузер несовместим с платформой». Неизвестные клиенты также не допускаются.

При включении обоих режимов действуют более строгие правила. Можно редактировать оба списка и минимальные основные версии движков, а также вернуть значения по умолчанию. Новые настройки, закрывающие доступ текущему суперадмину, отклоняются. Для изменения правил сначала нужно перейти в браузер, который будет разрешён.

## Версии и источники

Начальные минимумы на 30 октября 2026: Chromium 154, Firefox/ESR 153, Safari/iOS 26; для Яндекса в обычном режиме — Chromium 152. Отдельный минимум Яндекса также редактируется и не понижает порог других Chromium-браузеров. Проверяется основной номер версии; это не проверка каждого исправления CVE и не замена обновлений безопасности. Пороги необходимо пересматривать по мере обновления поддерживаемых браузеров.

Официальные сведения, использованные при выборе порогов: [Chrome Version History](https://versionhistory.googleapis.com/v1/chrome/platforms/linux/channels/stable/versions?pageSize=1), [Mozilla Product Details](https://product-details.mozilla.org/1.0/firefox_versions.json), [обновления безопасности Apple](https://support.apple.com/en-us/100100). На дату проверки опубликованы Chrome 156, Firefox 159 и ESR 153.6, Safari 27.2; Apple также публикует обновления ветки 26. В официальном [Linux-пакете Яндекса](https://browser.yandex.ru/download?beta=0&os=linux&package=deb&full=1) 26.10.0.1860 присутствует версия Chromium 152; поэтому общий минимум 154 нельзя применять к нему без отдельной настройки. Миграция 022 добавляет отдельный минимум в сохранённую JSON-политику, сохраняя прежние списки и переключатели, и меняет редакцию для повторной проверки браузеров. Контракт также поддерживает чтение первоначальной JSON-политики миграции 021.

## Проверка подмены и ограничения

Сервер сопоставляет HTTP User-Agent и Client Hints с данными страницы, независимого Web Worker и необходимыми возможностями. Порядок и произвольные GREASE-бренды Client Hints не считаются нарушением; версии продукта Opera или Яндекса не сравниваются с номером движка Chromium. Не запрашиваются камера, микрофон, экран, список устройств, шрифтов или графическое оборудование.

Несогласованная подмена блокируется. При смене заголовков, истечении проверки или изменении политики требуется повторная проверка. Подтверждение нельзя перенести в другой браузер простым параметром запроса или повторным использованием старого проверочного ответа. В усиленном режиме отсутствие распознанного браузера или подтверждения закрывает API и новые подключения сигнализации. По умолчанию обычный режим сохраняет поддержку служебных HTTP-клиентов без браузерных признаков; он не является списком разрешённых клиентов. При добавлении «Other / unknown» в список запрещённых такие клиенты также блокируются. Запросы браузера с Fetch Metadata проходят проверку и при замене User-Agent на неизвестный.

**Это не криптографическая аттестация браузера.** Все передаваемые веб-клиентом признаки потенциально подделываемы. Расширение с полным контролем страницы, workers и заголовков либо изменённый клиент может согласованно подменить их. Абсолютный запрет такого обхода обычный веб-сайт обеспечить не может. Некоторые Chromium-браузеры, включая Vanadium, могут представляться как Chrome/Chromium и не всегда различимы. Ограничения явно указаны в интерфейсе. Подробнее: [UA Client Hints](https://wicg.github.io/ua-client-hints/), [документация Chromium](https://developer.chrome.com/docs/privacy-security/user-agent-client-hints), [Vanadium](https://grapheneos.org/usage#web-browsing).

## Обновление и восстановление

Перед запуском обновлённого API применить миграции 021 и 022 через `npm run setup`. Существующие аккаунты, приглашения и учебные данные сохраняются. Состояние и подтверждения хранятся в PostgreSQL; проверочные записи имеют ограниченный срок хранения.

Если доступ потерян из-за правил браузеров или сети, оператор сервера выполняет `npm run security:reset` (для PGlite сначала остановить API). Команда выключает сетевое ограничение и оба режима браузеров, сохраняя списки и учебные данные. После входа суперадмин исправляет правила и снова включает нужную защиту. Публичного обхода проверки для администратора нет.
