# Защита браузеров

Суперадмин открывает `/admin?tab=security` → «Безопасность браузеров». Настройки сохраняются отдельной кнопкой. Изменения требуют текущей сессии суперадмина, CSRF и актуальной редакции, попадают в журнал действий. Новые правила применяются при следующем запросе; открытый интерфейс также обновляет проверку в фоне. Изменение не является блокировкой аккаунта и не меняет учебные результаты.

## Два режима

**«Защита от устаревших браузеров» по умолчанию включена.** Она запрещает выбранные семейства браузеров, версии ниже настроенного минимума и несовместимые возможности. По умолчанию ограничены Internet Explorer, Edge Legacy, Opera Mini, UC Browser, Puffin, QQ Browser и WebView. Это редактируемая политика совместимости, а не утверждение о небезопасности всех выпусков этих продуктов.

Актуальный Яндекс Браузер допускается. После первого входа пользователь видит «Ваш браузер может быть несовместим с платформой». Кнопка «Понятно» сохраняет подтверждение для аккаунта и семейства браузера; обновление страницы и следующий вход его не сбрасывают. Для гостя подтверждение сохраняется в текущем браузере, без создания обычного аккаунта.

**«Усиленная защита» по умолчанию выключена.** Она допускает только распознанные семейства из разрешённого списка и требует действующую проверку браузера для API. По умолчанию разрешены Chrome, Chromium, Opera, Vanadium, Edge, Firefox, Safari, Brave, Vivaldi, Samsung Internet и DuckDuckGo. Без ручного допуска суперадмина Яндекс Браузер запрещён, включая административный вход; добавить его в обычный список разрешённых нельзя. При отказе показывается «Ваш браузер несовместим с платформой». Неизвестные клиенты также не допускаются.

При включении обоих режимов действуют более строгие правила. Можно редактировать оба списка и минимальные основные версии движков, а также вернуть значения по умолчанию. Новые настройки, закрывающие доступ текущему суперадмину, отклоняются. Для изменения правил нужен разрешённый браузер либо действующий ручной допуск текущего браузера.

## Версии и источники

Минимумы по умолчанию с 31 октября 2026: Chrome/Chromium 134, Firefox/ESR 153, Safari/iOS 26; для Яндекса в обычном режиме — Chromium 152. Chrome 134 и новее допускается в обоих режимах при согласованных признаках и необходимых возможностях. Пороги редактируются. Миграция 025 заменяет прежний общий минимум 154 на 134, сохраняя другие настроенные значения, списки и переключатели. Отдельный минимум Яндекса не применяется к Chrome. Проверяется основной номер версии; это не проверка каждого исправления CVE и не замена обновлений безопасности.

Официальные сведения, использованные при выборе порогов: [Chrome Version History](https://versionhistory.googleapis.com/v1/chrome/platforms/linux/channels/stable/versions?pageSize=1), [Mozilla Product Details](https://product-details.mozilla.org/1.0/firefox_versions.json), [обновления безопасности Apple](https://support.apple.com/en-us/100100). На дату проверки опубликованы Chrome 156, Firefox 159 и ESR 153.6, Safari 27.2; Apple также публикует обновления ветки 26. В официальном [Linux-пакете Яндекса](https://browser.yandex.ru/download?beta=0&os=linux&package=deb&full=1) 26.10.0.1860 присутствует версия Chromium 152; поэтому общий минимум 154 нельзя применять к нему без отдельной настройки. Миграция 022 добавляет отдельный минимум в сохранённую JSON-политику, сохраняя прежние списки и переключатели, и меняет редакцию для повторной проверки браузеров. Контракт также поддерживает чтение первоначальной JSON-политики миграции 021.

## Проверка подмены и ограничения

Сервер сопоставляет HTTP User-Agent и Client Hints с данными страницы, независимого Web Worker и необходимыми возможностями. Порядок и произвольные GREASE-бренды Client Hints не считаются нарушением; версии продукта Opera или Яндекса не сравниваются с номером движка Chromium. Не запрашиваются камера, микрофон, экран, список устройств, шрифтов или графическое оборудование.

Несогласованная подмена блокируется. При смене заголовков, истечении проверки или изменении политики требуется повторная проверка. Подтверждение нельзя перенести в другой браузер простым параметром запроса или повторным использованием старого проверочного ответа. В усиленном режиме отсутствие распознанного браузера или подтверждения закрывает API и новые подключения сигнализации. По умолчанию обычный режим сохраняет поддержку служебных HTTP-клиентов без браузерных признаков; он не является списком разрешённых клиентов. При добавлении «Other / unknown» в список запрещённых такие клиенты также блокируются. Запросы браузера с Fetch Metadata проходят проверку и при замене User-Agent на неизвестный.

**Это не криптографическая аттестация браузера.** Все передаваемые веб-клиентом признаки потенциально подделываемы. Расширение с полным контролем страницы, workers и заголовков либо изменённый клиент может согласованно подменить их. Абсолютный запрет такого обхода обычный веб-сайт обеспечить не может. Некоторые Chromium-браузеры, включая Vanadium, могут представляться как Chrome/Chromium и не всегда различимы. Ограничения явно указаны в интерфейсе. Подробнее: [UA Client Hints](https://wicg.github.io/ua-client-hints/), [документация Chromium](https://developer.chrome.com/docs/privacy-security/user-agent-client-hints), [Vanadium](https://grapheneos.org/usage#web-browsing).

## Обновление и восстановление

Перед запуском обновлённого API применить миграции 021 и 022 через `npm run setup`. Существующие аккаунты, приглашения и учебные данные сохраняются. Состояние и подтверждения хранятся в PostgreSQL; проверочные записи имеют ограниченный срок хранения.

Если доступ потерян из-за правил браузеров или сети, оператор сервера выполняет `npm run security:reset` (для PGlite сначала остановить API). Команда выключает сетевое ограничение и оба режима браузеров, сохраняя списки и учебные данные. После входа суперадмин исправляет правила и снова включает нужную защиту. Автоматического публичного обхода для роли администратора нет. Суперадмин может заранее выдать отдельную ссылку ручного допуска, описанную ниже.

## Разрешить вход вручную

В `/admin?tab=security` появился отдельный раздел «Разрешить вход вручную». Только суперадмин создаёт ссылки, читает историю и отзывает допуски. При создании задаются название, одноразовое или многоразовое использование и необязательный срок ссылки. Ссылку можно скопировать сразу и позднее открыть в истории. Повтор сохранения после потерянного ответа возвращает прежнюю ссылку.

Получатель открывает ссылку и нажимает «Разрешить этот браузер»; простое открытие не расходует одноразовую ссылку. Можно указать понятное название устройства. Страница подтверждения работает без JavaScript и не требует прохождения проверки браузера. После подтверждения платформа запоминает текущий браузер/профиль до 365 дней. В нём обходятся оба режима защиты браузеров, включая проверку подмены и Worker. Авторизация, пароль, 2FA, роли, капча и сетевые правила сохраняются. Ручной допуск не обеспечивает техническую совместимость старого браузера с функциями приложения.

История показывает автора ссылки, дату, тип, срок, состояние, общее и активное количество допусков. В раскрываемом списке доступны название браузера/профиля, семейство браузера и ОС, переданные сведения User-Agent, первый и последний IP, первое и последнее обращение, срок допуска и последний вошедший аккаунт, если он был. Время последнего обращения обновляется с точностью примерно до минуты; смена вошедшего аккаунта фиксируется отдельно. Эти сведения не являются подтверждённой аппаратной идентификацией.

Одноразовая ссылка выдаёт один допуск; повтор того же получателя не создаёт вторую запись. Многоразовая подходит нескольким профилям. Один и тот же уже допущенный профиль не расходует ещё одну ссылку. Удаление cookie, другой браузер или профиль требуют нового допуска; одно физическое устройство может иметь несколько записей.

Срок ссылки ограничивает новые подтверждения и не отменяет уже выданные допуски. Можно отозвать отдельный допуск или ссылку целиком. Отзыв ссылки закрывает все её допуски при следующей проверке API/нового подключения; история и авторы сохраняются. Владелец действующей многоразовой ссылки может получить новый допуск, поэтому для закрытия всех выданных ею разрешений отзывайте саму ссылку. Изменения попадают в аудит.

Обновление требует миграции **024** через `npm run setup` перед запуском API; прежние миграции, аккаунты и учебные данные сохраняются. Проверки — [протокол ручного допуска и интерфейса встреч](ACCEPTANCE_BROWSER_MANUAL_MEETING_UI.md).
