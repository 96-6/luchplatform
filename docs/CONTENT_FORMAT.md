# Учебный контент: формат v1

Формат `luch-content` предназначен для переноса учебных материалов между установками ЛУЧ. Один JSON-пакет содержит маршруты, упорядоченные уроки, навыки, задания, наборы и описания медиа. Ответы пользователей, аккаунты и прогресс в него не входят.

Готовый пример — [демо-пакет](../content/demo/luch-demo.json). Машиночитаемая структура — [JSON Schema](../content/schema/luch-content-v1.schema.json); общий исполняемый контракт — `packages/contracts/src/content.ts`. JSON Schema проверяет структуру, а `content:validate` и импорт дополнительно проверяют связи, языки, уровни, варианты ответа и разделение банков.

## Сущности и ссылки

| Поле пакета               | Содержимое                                                                                                                                      |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `format`, `formatVersion` | `luch-content`, `1`: версия формата обмена                                                                                                      |
| `package`                 | ID пакета, версия публикации, название, автор, лицензия, признак демо                                                                           |
| `routes`                  | Язык `ru`/`en`, уровень `A1`/`A2`, цели и **упорядоченный** список `lessonIds`                                                                  |
| `lessons`                 | Маршрут, краткое описание, минуты, `skillIds`, блоки материала                                                                                  |
| `skills`                  | Описание проверяемого действия, язык и уровень                                                                                                  |
| `exercises`               | Версия, урок, один проверяемый навык, режим, инструкция, материал, ответ, решение, объяснение, подсказки, рубрика, авторство и статус редактуры |
| `sets`                    | Маршрут, режим и **упорядоченный** список `exerciseIds`                                                                                         |
| `assets`                  | Тип, ссылка, MIME, автор, лицензия и необязательная SHA-256                                                                                     |

ID — до 80 символов: латинские строчные буквы, цифры и дефисы. Они уникальны внутри своего типа в пакете. Ссылки между пакетами не допускаются. Полная ссылка для последующих попыток: `{ packageId, packageVersion, exerciseId, exerciseVersion }`. Текущий каталог показывает последнюю опубликованную версию, а ссылка с `packageVersion` читает конкретную сохранённую версию.

## Учебный материал

Каждый блок имеет `id` и `type`. Блоки выводятся в порядке массива.

| `type`       | Поля и отображение                                             |
| ------------ | -------------------------------------------------------------- |
| `text`       | `text`, необязательный `heading`: обычный текст с переносами   |
| `vocabulary` | `items`: `term`, `translation`, необязательный `example`       |
| `dialogue`   | `lines`: `speaker`, `text`                                     |
| `image`      | `assetId`, обязательный `alt`, необязательный `caption`        |
| `audio`      | `assetId`, обязательный `transcript`, необязательный `caption` |
| `video`      | `assetId`, обязательный `transcript`, необязательный `caption` |
| `file`       | `assetId`, `label`, необязательный `description`               |

Произвольный HTML, скрипты и iframe не являются блоками формата. Аудио и видео открываются стандартным браузерным проигрывателем; текст записи доступен отдельно. Допускаются SVG/PNG/JPEG/WebP, MPEG/WAV/OGG, MP4/WebM, PDF и TXT с соответствующим типом материала.

Медиа передаются **отдельно от JSON**. Для собственных файлов используйте `/learning-media/...`: положите их в `apps/web/public/learning-media/` до сборки, а затем импортируйте пакет. В собранном приложении они находятся в `apps/web/dist/learning-media/`. При импорте локальный файл должен существовать; указанная контрольная сумма должна совпасть. Альтернатива — HTTPS-ссылка без логина и пароля. Импорт не скачивает внешние материалы и не подтверждает доступность стороннего сервера.

Для новых редакций медиа используйте новые имена, например `dialogue-ru-v2.mp3`, и сохраняйте старые файлы. Версии материалов нельзя менять по прежним ссылкам, если они использованы в сохранённых заданиях. JSON-экспорт переносит ссылку и метаданные, но не создаёт архив с бинарными файлами.

## Ответы и отдельные банки

- `choice`: несколько вариантов с ID; в `solution.correctOptionIds` ровно один правильный вариант.
- `short_text`: ограничение длины; в `solution.accepted` допустимые ответы и явные правила нормализации: края, пробелы, регистр и Unicode NFKC. Импорт сохраняет варианты дословно; luch engine применяет указанные правила на сервере, сохраняя исходный ответ ученика без преобразования.
- У каждого задания есть объяснение и рубрика с собственной версией. В демо максимальная оценка — 1.

Режимы — `diagnostic`, `practice`, `control`. Набор может содержать только задания своего режима и маршрута. Это разные задания с отдельными ID; тренировочный ответ не является ответом на контрольное задание. Контрольные задания не содержат подсказок. В рабочем пакете контроль требует `review.status=approved`, имя методиста и дату; демонстрационные задания помечены `demo` и не заявлены как утверждённый экзамен.

Каталог возвращает инструкцию, материал и форму ответа. Решение, объяснение, подсказки и рубрика остаются в серверном банке. **luch engine** проверяет ответы по закреплённой редакции: в тренировке выдаёт подсказки по запросу и объяснение после ответа; в диагностике и контроле открывает результаты после завершения набора. Правильные варианты будущих вопросов не передаются ученику. Прохождения и ответы хранятся отдельно от контентного пакета; изменение каталога не меняет их историю. См. [ENGINE.md](ENGINE.md).

## Импорт, экспорт и версии

После `npm ci` и `npm run setup`, из корня репозитория:

```bash
npm run db:seed-demo
# Только контент, без создания аккаунтов:
npm run content:seed-demo

npm run content:validate -- --file content/demo/luch-demo.json
npm run content:import -- --file ./my-course.json
npm run content:export -- --package luch-demo --file ./luch-demo-export.json
# Экспорт сохранённой редакции:
npm run content:export -- --package luch-demo --version 1 --file ./luch-demo-v1.json
```

Для локального PGlite сначала остановите API. Экспорт пишет новый файл и не перезаписывает существующий. Максимальный размер JSON — 2 МиБ. Проверка файла не открывает базу.

В кабинете суперадмина раздел «Учебный контент» позволяет выбрать JSON, увидеть состав, импортировать пакет и скачать экспорт. Экспорт включает правильные ответы; он доступен суперадмину и оператору CLI.

Повтор пакета с теми же ID, версией и содержимым не создаёт записей. Порядок ключей JSON и форматирование не влияют на повтор. Другое содержимое под существующей версией отклоняется. Новая редакция увеличивает `package.version`; изменение задания увеличивает его `version`, изменение критериев — также `rubric.version`. Эти правила действуют и для задания, удалённого из промежуточной редакции и затем возвращённого.

Импорт публикует весь пакет в одной транзакции. Ошибка не оставляет частично загруженных уроков. Старые редакции сохраняются. Повторная загрузка демо v1 после публикации v2 не откатывает каталог. Импорт разных пакетов не меняет существующие пакеты. Параллельные повторы одного пакета создают одну редакцию.

Обновление структурной схемы: `npm run content:schema`. База обновляется отдельной неизменяемой миграцией `003_learning_content.sql`; расширение формата не требует отдельного приложения.
