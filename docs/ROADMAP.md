# Порядок разработки

Задачи выполняются по порядку; внутри задачи — по номерам подзадач. Переход к следующей задаче допускается после проверки результата текущей. Новые этапы расширяют этот репозиторий и его миграции, без нового отдельного приложения.

## Задача 1 — техническая основа

**Статус: выполнена и проверена.**

| Подзадача                   | Реализация                                          |
| --------------------------- | --------------------------------------------------- |
| 1.1 Проект и репозиторий    | Существующий `96-6/luchplatform`                    |
| 1.2 Клиент, сервер, база    | React/Vite, Fastify, PostgreSQL с двумя драйверами  |
| 1.3 Окружение               | Примеры, валидация, отдельные серверные ключи       |
| 1.4 Общий интерфейс         | Логотип, меню, содержание, мобильная навигация      |
| 1.5 Состояния               | Загрузка, пустые данные, ошибка и повтор            |
| 1.6 Запуск и структура базы | `setup`, `dev`, `build`, `start`, миграции и Docker |

Критерий: запуск по инструкции, открытие в браузере, запись в базе. Свидетельства и ограничения — в [протоколе задачи 1](ACCEPTANCE_TASK_1.md).

## Задача 2 — вход и роли

**Статус: выполнена и проверена.**

Реализованы 2.1–2.6, подтверждение почты, Authenticator, собственная капча и кабинет суперадмина. Проверка и ограничения — в [протоколе задачи 2](ACCEPTANCE_TASK_2.md).

## Задача 3 — учебная структура и демо-контент

**Статус: выполнена и проверена.**

Реализованы 3.1–3.6: 2 маршрута, 12 мини-уроков, 12 навыков, 48 заданий и 6 отдельных наборов. Добавлены формат JSON v1, импорт/экспорт и версии банка. Свидетельства — в [протоколе задачи 3](ACCEPTANCE_TASK_3.md), формат — в [описании контента](CONTENT_FORMAT.md).

## Задача 4 — luch engine

**Статус: выполнена и проверена.**

Реализованы 4.1–4.6: материал и инструкция, выбор и короткий текст, серверная проверка, подсказки и объяснения, транзакционное сохранение попыток, переходы и продолжение после повторного входа. Добавлены полный доступ суперадмина с записью автора действий и переключаемая фоновая проверка прохождения. Свидетельства — в [протоколе задачи 4](ACCEPTANCE_TASK_4.md), устройство учебного модуля — в [ENGINE.md](ENGINE.md).

## Задача 5 — анкета и входная диагностика

**Статус: реализована, локальные проверки пройдены; ожидается CI.**

Реализованы 5.1–5.6: анкета с версиями, диагностические наборы обоих языков через luch engine, предварительный результат по навыкам, сильные стороны/затруднения и продолжение после перерыва. Дополнительно добавлены локальное управление аккаунтами, создание готового пользователя и управление 2FA суперадмином. Свидетельства — в [протоколе задачи 5](ACCEPTANCE_TASK_5.md), структура — в [DIAGNOSTICS.md](DIAGNOSTICS.md).

| --- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------- |

| 8   | Главная ученика, сегодняшние задания, продолжение и прогресс                 | Обучение начинается с главной без поиска задания                           |

| 10  | Запись, STT, подтверждение, TTS и корректировка                              | Произнесённый ответ приводит к обратной связи и заданию; сбой не штрафует  |
| 11  | Ученики преподавателя, проверка ответа и изменения плана                     | Учитель меняет оценку/назначение, ученик видит сохранённое изменение       |
| 12  | Расписание, индивидуальные/групповые видеозанятия и домашняя работа          | Участники входят в комнату из кабинета, затем получают домашнее задание    |
| 13  | Отчёт по действиям, самостоятельность, помощь и подтверждение                | Ученик и его преподаватель видят один актуальный отчёт                     |
| 14  | HTTPS, оба полных сценария, повторы, сбои, мобильный доступ и восстановление | Платформа доступна по ссылке, учебный путь работает без ручной правки базы |

Для каждого этапа добавлять собственный протокол с исходными данными, действиями, ожидаемым и фактическим результатом. В общем CI сохранять проверки предыдущих этапов.

## Требования исходного ТЗ для дальнейшего учёта

Исходный документ также требует администраторский доступ, связь с общей учётной записью ЛУЧ, пробные права/лимиты и проверяемую подпись отчёта. Администраторский доступ добавлен задачей 2. Общий вход ЛУЧ, пробные права/лимиты и подпись отчёта ещё не реализованы. Учитывать их при детализации соответствующих этапов; внешние API подключать только после проверки реального доступа.
