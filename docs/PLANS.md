# Первоначальный индивидуальный план — задача 6

План формируется на сервере из сохранённой диагностики, её анкеты и закреплённой редакции банка. Демо-маршрут даёт шесть тренировочных мини-уроков, по два задания в каждом. Ответы, подсказки, черновики и попытки обрабатывает тот же luch engine.

## Правила 1.0.0

1. Выбирается маршрут и язык диагностики. Включаются его уроки с заданиями `practice`; диагностические и контрольные задания в план не переходят.
2. Первыми идут уроки по навыкам с ошибками: сохранено меньше верных ответов, чем проверенных вопросов. Причина `diagnostic_gap` содержит название навыка и число верных ответов.
3. Затем — навыки с успехом, который пока не был самостоятельным. Причина `guided_success` рекомендует самостоятельную практику без изменения исходной оценки.
4. Внутри этих групп и среди остальных уроков учитывается цель. При одинаковом приоритете сохраняется порядок маршрута.
5. Остальные уроки сохраняются как следующие шаги маршрута. Предварительный успех не исключает дальнейшую практику.

Приоритеты тем текущего банка одинаковы для обоих языков:

| Цель                 | Тематический порядок                                    |
| -------------------- | ------------------------------------------------------- |
| Повседневное общение | Знакомство → семья → планы → кафе → время → направление |
| Путешествия          | Направление → кафе → время → знакомство                 |
| Работа               | Знакомство → время → планы                              |
| Учёба                | Время → знакомство → планы                              |

Соответствие использует ID навыков `ru-*` и `en-*` из демо-банка. Неизвестные тематическим правилам навыки импортированного пакета получают порядок маршрута и причины по своей диагностике. Расширение правил требует новой версии алгоритма и не переписывает прошлые планы. Например, при цели «Путешествия» и успешной диагностике первым будет «Место и направление»; при ошибке по времени первым станет «Время и расписание» с причиной из результата.

Минуты в день определяют рекомендуемый день. Уроки последовательно помещаются в дневной бюджет по `estimatedMinutes`, при превышении начинается следующий день. Урок длиннее бюджета получает отдельный день; его можно прервать и продолжить. У первоначальных назначений дат и дедлайнов нет; у адаптивных повторений сохраняется дата доступности. Для уроков по семь минут бюджет 20 минут даёт три дня, пять минут — шесть. Опыт сохраняется в снимке анкеты; отдельного разветвления по нему в текущем единственном уровне A1 нет.

## Хранение

Миграция 008 добавляет:

- `learning_plans`: владелец, единственная исходная диагностика, маршрут, редакция банка, версия правил, автор и дата;
- `plan_assignments`: порядок, урок, рекомендуемый день, длительность, причина, связанный run, автор и дата запуска;
- `plan_assignment_exercises`: точные ID/версии тренировочных заданий в порядке исполнения.

Анкета читается из исходной диагностики. Причина сохраняет тип, объяснение, цель и наблюдения по навыкам. Внешние ключи защищают владельца, маршрут, банк и прохождение от смешивания. API плана не выдаёт решения.

Последний переход диагностики сохраняет итог по навыкам и план одной транзакцией. Ошибка сохранения плана откатывает завершение и частичные записи; уже отправленный последний ответ остаётся, переход можно повторить. Уникальная исходная диагностика и блокировка защищают конкурентные повторы.

Для результатов до миграции 008 доступен явный `POST /plans` со страницы результата. Чтение не создаёт назначения. Если импортированный маршрут вообще не имеет тренировочного банка, результат диагностики сохраняется без выдуманных заданий; явное формирование возвращает `PLAN_CONTENT_UNAVAILABLE`. Демо-маршруты имеют полный банк для плана.

Новая диагностика создаёт отдельный план. Изменение анкеты, публикация банка и обновление правил не меняют прошлые причины и задания. Планы обоих языков доступны в истории с пагинацией.

## Запуск и статусы

Назначение вызывает `LuchEngine.startInTransaction`. Создание или выбор run и привязка выполняются одной транзакцией; состав шагов сверяется с сохранёнными ссылками. Повтор запуска возвращает тот же run, в том числе после завершения.

Подходящий незавершённый урок той же редакции продолжается. Одно такое прохождение может связывать назначения нескольких исторических планов; завершение отражается в каждом. Завершённый сторонний урок получает новый цикл. Повтор урока после завершения назначения не заменяет его первоначальную историю.

Статусы основаны на базе: `pending` без run, `active` при активном run, `completed` после последнего перехода. Правильность ответа не подменяет факт завершения: урок с ошибкой тоже может быть завершён. Общий прогресс читается из связанных прохождений; отдельного клиентского флага «выполнено» нет.

`nextAssignmentId` — активное либо следующее доступное назначение с учётом адаптации и дат повторений. Кнопка открывает его первый или текущий шаг. Отдельные уроки также доступны из списка. Перерыв, обновление страницы и повторный вход сохраняют run, попытки и черновик.

## Доступ и развитие

Ученик читает и запускает свои назначения. Преподаватель читает планы закреплённых учеников. Суперадмин читает любые планы, формирует их по сохранённой диагностике и запускает любые назначения; автор сохраняется. Управление чужим планом включается отдельно на экране.

`/plan` показывает историю, `/plan/:id` — последовательность, причины, рекомендуемые дни и прогресс. Из диагностики, кабинетов и упражнения есть переходы к одному и тому же плану.

Задача 7 добавляет коррекцию после ошибки, самостоятельную практику после помощи, отсроченную проверку после успеха и датированную историю. Первоначальные причины и оценки остаются. Одно дополнительное назначение открывает отдельный run с `sourceType=assignment`, точной ссылкой на упражнение и необязательным ID сгенерированного варианта.
