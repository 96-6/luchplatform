# Прогресс и учебный отчёт — задача 13

Страница `/progress` строится по сохранённым действиям luch engine, диагностике, проекциям навыков, планам и проверкам преподавателя. Ученик открывает собственный отчёт из меню или главной. Преподаватель — из списка/карточки закреплённого ученика либо выбирает ученика на странице отчёта. Суперадмин может выбрать любого ученика; служебная роль администратора не получает учебный доступ.

Общая ссылка: `/progress?userId=UUID&language=ru` (или `en`). Она требует входа и действующих прав; сама ссылка доступа не предоставляет. Общий объект `report` одинаков для ученика и его преподавателя. Приватная часть `reviewer` доступна преподавателю этого ученика и суперадмину, у ученика она равна `null`.

## Что учитывается

- Все отправленные попытки выбранного языка, текущие и исходные оценки, самостоятельность и сохранённые признаки помощи: подсказки, помощник, обратная связь, участие другого пользователя.
- Выполненные шаги и уникальные задания, завершённые прохождения и назначения. Повтор одного задания увеличивает число попыток/шагов, но не число уникальных заданий. Отмена не считается выполнением. «Уроки из каталога» — полные тренировочные прохождения источника `lesson`.
- Сохранённое состояние каждого навыка из адаптации, текущие результаты по нему и попытки, ещё ожидающие обработки учебного события/завершения назначения. Состояния не пересчитываются вторым учебным движком при чтении отчёта.
- Повторяющиеся ошибки: навыки с двумя и более ошибочными попытками по текущим оценкам; число попыток, разных заданий и ссылка на последний ответ. Исправление преподавателя сразу учитывается, исходные автоматические ошибки остаются видны отдельно.
- История автоматических и преподавательских изменений плана с датой, автором, сохранённой причиной и ссылкой на ответ-основание. В неё входят назначения после видеозанятий через прежний модуль преподавателя.
- Продолжение текущего прохождения и следующие существующие назначения. Ожидающие адаптивные задания старых планов сохраняются в списке, прежние не начатые первоначальные назначения заменённого плана не выдаются за текущую очередь.

Самостоятельность берётся из сохранённой попытки. Уже показанное объяснение/решение может учитываться как обратная связь в повторном цикле. Распознавание речи само по себе помощью не считается; технические ошибки STT/TTS, видеосвязи и сети не создают учебных попыток.

«Проверено преподавателем» пересекается с самостоятельными ответами и помощью. Для каждой попытки учитывается последнее оценочное решение `confirm`/`correct`; комментарий не отменяет его. Полная история проверок доступна по ссылке конкретного ответа. Первоначальная диагностика остаётся предварительным снимком, последующие исправления отражаются в текущих результатах отдельно.

Оценки незавершённых диагностики/контроля исключены из общих показателей, повторяющихся ошибок и приватных весов. Показывается только число ожидающих завершения ответов; мини-карточки получают `correct=null`, `automaticCorrect=null`, `independent=null`.

## Приватные веса наблюдений

Для преподавателя и суперадмина показаны сохранённый контекст попыток, версия правил веса, число попыток с/без достаточных данных, вклады отдельных видов наблюдений и результат до/после применения весов. Это условные веса свидетельств самостоятельного результата, требующие человеческой проверки, а не вероятность нарушения.

Базовая единица свидетельства — один успешный самостоятельный ответ. Из неё вычитаются ограниченные вклады сохранённых наблюдений конкретной попытки; общий предел снижения — 30%. Повтор одного вида в той же попытке не увеличивает его вес. При ограничении вклады распределяются пропорционально; целочисленные базисные пункты обеспечивают точное сложение. Общий учебный балл, состояние навыка, помощь и план от этих расчётов не меняются.

При недостаточных данных вес не снижается; отсутствие наблюдений не считается подтверждением честности. Неизвестные виды сигналов в текущей версии не получают снижение. Проверка правильности преподавателем сохраняется отдельно и не удаляет исходные наблюдения. Не привязанные к конкретной учебной попытке сигналы видеоустройств не превращаются в учебные штрафы.

Приватные расчёты выполняются только после серверной проверки прав. Ученику не передаются наблюдения, их вклады или скорректированные единицы. Проверки клавиатуры, сенсорного ввода и доступности остаются в существующем модуле luch engine; отчёт не вводит новый сбор данных.

## Актуальность, объём и хранение

Каждое чтение использует одну транзакцию `REPEATABLE READ READ ONLY`. Показатели SQL считаются по всей истории, страницы попыток/изменений/наблюдений используют устойчивый курсор `(дата, UUID)`. Ограничение страницы не ограничивает общие показатели. Для отчёта нет копии ответов, отдельной оценки или браузерного хранилища результатов.

Страница обновляется автоматически, при возвращении в окно и кнопкой «Обновить отчёт». `revision` зависит от общей части данных; приватные веса в неё не входят. `refreshedAt` находится вне общего объекта. Две роли читают один и тот же актуальный набор фактов. При изменении общей версии история загружается заново, чтобы не сохранять устаревшие оценки в уже показанных строках.

Языки и редакции учебного банка разделены. Используется последняя сохранённая анкета соответствующего языка; новое значение профиля не переписывает прежние диагностики/планы. Навыки прежней редакции с результатами сохраняют свои названия, навыки нового банка без результатов показываются без оценки.

## Обновление и проверки

Новые внешние ключи сервисов не нужны. Миграция **015** добавляет индексы чтения/пагинации поверх существующих таблиц; миграции 001–014 неизменны.

Обычное обновление: остановить API, получить код, `npm ci`, `npm run setup`, `npm run build`, затем запустить приложение прежней командой. Compose применяет миграцию отдельным процессом перед API. Сохранённые ответы, планы, занятия и проверки используются напрямую.

Проверки: `apps/api/test/reports.test.ts`, `tests/e2e/reports.spec.ts`, `scripts/report-smoke.mjs`. Последний запускается в изолированной базе разработки/тестов при `ENABLE_DEV_TOOLS=true`; CI выполняет создание и `verify` в разных процессах с перезапуском API.
