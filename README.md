# ЛУЧ — образовательная платформа

Исходный код демоверсии РКИ и английского. Реализуется последовательность задач из [плана разработки](docs/ROADMAP.md). Реализованы задачи **1–3: техническая основа, аккаунты и учебный контент**. Доступны два маршрута по шесть мини-уроков и просмотр заданий. Прохождение и проверка ответов относятся к задаче 4 (luch engine).

Основа: TypeScript, React/Vite, Fastify, PostgreSQL. Для локальной разработки PostgreSQL работает внутри процесса через PGlite и сохраняет данные на диск. На хостинге используется отдельный PostgreSQL через `pg`; API, SQL и миграции общие для обоих режимов.

## Быстрый запуск

Нужны Node.js 24 и npm 11. Docker для этого варианта не требуется.

```bash
git clone https://github.com/96-6/luchplatform.git
cd luchplatform
npm ci
npm run setup
npm run db:seed-demo
npm run db:smoke
npm run db:verify-smoke
npm run dev
```

Открыть **http://localhost:5173**. API: http://127.0.0.1:3000. В меню есть «Проверка системы»: сохранить запись и обновить страницу — запись остаётся в базе. Можно остановить приложение, запустить снова и проверить тот же список. `db:verify-smoke` читает запись, созданную `db:smoke`, уже в другом процессе.

`setup` подготавливает `.env`, добавляет недостающие параметры и применяет миграции. Существующие значения сохраняются; необходимые локальные ключи создаются автоматически. Данные хранятся в `data/luch`; эта папка и `.env` исключены из Git. Остановка — Ctrl+C.

**Для PGlite сначала остановите API, затем запускайте команды базы.** Разрешён один процесс на каталог базы; блокировка защищает от одновременного открытия CLI и сервером. Если нужен общий доступ нескольких процессов, используйте обычный PostgreSQL.

## Вход и демонстрационные аккаунты

После `db:seed-demo` доступны `student@example.test`, `teacher@example.test` и `admin@example.test`. Откройте «Демо-почта» со страницы входа, подтвердите адрес, отсканируйте QR приложением Authenticator и введите его код. Для дальнейшего входа нужны почта и текущий шестизначный код. Демонстрационный преподаватель уже связан с демонстрационным учеником.

Обычная регистрация доступна ученикам и преподавателям. Суперадмин создаётся серверной командой:

```bash
npm run admin:create -- --email your-address@example.com --name "Администратор"
```

В production письма отправляются через параметры `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`. Локальная демо-почта в production недоступна. Реальные почтовые доступы не включаются в репозиторий.

В кабинете суперадмина доступны аккаунты пользователей, назначения преподавателей, настройки безопасности и журнал действий. Учебный прогресс будет добавлен с учебными модулями; текущая версия не показывает выдуманные результаты.

## Учебные материалы

`db:seed-demo` загружает аккаунты и учебный пакет без дубликатов. После входа откройте «Маршруты»: РКИ и английский, по шесть мини-уроков. Всего 12 навыков и 48 заданий: по 6 диагностических, 12 тренировочных и 6 контрольных заданий на язык. Материалы демонстрационные, с явной маркировкой; ответы пока не принимаются.

Суперадмину доступен раздел «Учебный контент» с импортом и экспортом JSON. Решения заданий доступны только в служебном экспорте. Повтор импорта не дублирует материалы; новые редакции сохраняют прежние версии.

```bash
npm run content:validate -- --file content/demo/luch-demo.json
npm run content:import -- --file ./my-course.json
npm run content:export -- --package luch-demo --file ./luch-demo-export.json
```

Описание сущностей, блоков материала, медиа, версий и правил переноса — в [формате контента](docs/CONTENT_FORMAT.md). Для локального PGlite сначала остановите API перед импортом или экспортом.

## Параметры доступа

Капча и проверка сетевого доступа переключаются суперадмином. Доступ в ограниченном режиме зависит от проверки аккаунта и белого списка IP. При срабатывании сетевой проверки сайт и API возвращают отказ с сообщением «вы используете VPN - сервис недоступен».

Для размещения задаются доверенные адреса reverse proxy в `TRUST_PROXY_CIDRS`; дополнительный серверный источник сетевых данных подключается через `IP_INTEL_URL` и `IP_INTEL_KEY`. Неполученные измерения остаются неизвестными. Классификация соединения не является доказательством использования VPN.

При потере доступа после изменения сетевых настроек оператор сервера может выполнить `npm run security:reset` (для локальной базы сначала остановить API). Настройки и реальные секреты окружения не публикуются.

## Команды

| Команда                   | Результат                                                             |
| ------------------------- | --------------------------------------------------------------------- |
| `npm ci`                  | Установка зависимостей из lock-файла                                  |
| `npm run setup`           | Подготовка локального окружения и базы                                |
| `npm run dev`             | Клиент и API с обновлением при изменении кода                         |
| `npm run db:migrate`      | Применение новых миграций; повтор не создаёт таблицы заново           |
| `npm run db:smoke`        | Сохранение одной повторяемой тестовой записи                          |
| `npm run db:verify-smoke` | Чтение сохранённой записи в новом процессе                            |
| `npm run typecheck`       | Проверка типов во всех пакетах                                        |
| `npm test`                | API, миграции, повторные запросы, сбои и сохранение на диск           |
| `npm run build`           | Сборка общего контракта, сервера и клиента                            |
| `npm start`               | Запуск собранного API; при `SERVE_WEB=true` он отдаёт и клиент        |
| `npm run test:e2e`        | Проверки браузера на собранном приложении с отдельной временной базой |
| `npm run verify`          | Форматирование, типы, API, сборка и браузерные проверки               |

Для браузерных проверок один раз выполнить `npx playwright install chromium` (в Linux могут понадобиться системные зависимости: `npx playwright install --with-deps chromium`). Перед `test:e2e` нужна сборка `npm run build`. Тесты не используют вашу локальную базу.

## Конфигурация

Полный пример — [.env.example](.env.example). Сервер читает `.env` в корне проекта; переменные процесса имеют приоритет. Неизвестное значение флага, неверный порт или адрес приводят к отказу запуска с названием проблемного параметра.

| Параметр                             | Назначение                                                                    |
| ------------------------------------ | ----------------------------------------------------------------------------- |
| `APP_ENV`                            | `development`, `test` или `production`                                        |
| `APP_URL`                            | Полный origin приложения; разрешённый адрес браузерных запросов               |
| `API_HOST`, `API_PORT`               | Адрес и порт API; в контейнере host `0.0.0.0`                                 |
| `WEB_PORT`                           | Порт Vite в разработке                                                        |
| `DATABASE_URL`                       | `pglite:./data/luch` локально или `postgresql://user:password@host:5432/luch` |
| `DATABASE_SSL`                       | `true` для TLS к внешней базе с проверкой сертификата                         |
| `ENABLE_DEV_TOOLS`                   | Тестовые записи и проверка системы; по умолчанию выключены                    |
| `SERVE_WEB`                          | Раздача собранного клиента сервером                                           |
| `LOG_LEVEL`                          | `debug`, `info`, `warn`, `error`, `silent`                                    |
| `AI_API_URL`, `AI_API_KEY`           | Серверные параметры будущего помощника                                        |
| `SPEECH_API_URL`, `SPEECH_API_KEY`   | Серверные параметры будущего речевого сервиса                                 |
| `VIDEO_SERVICE_URL`, `VIDEO_API_KEY` | Серверные параметры будущего видеосервиса                                     |

Внешние сервисы в задаче 1 не вызываются и ключи не требуются. Они не передаются клиенту. Для production обязательны отдельный PostgreSQL, HTTPS в `APP_URL`, `ENABLE_DEV_TOOLS=false`, постоянный `AUTH_ENCRYPTION_KEY` и настроенный SMTP (`MAIL_MODE=smtp`). Рабочий URL, TLS и аккаунты хостинга подключаются на этапе размещения.

## PostgreSQL и контейнеры

```bash
node scripts/setup.mjs --compose
# Задать POSTGRES_PASSWORD в .env.compose.
docker compose --env-file .env.compose up --build -d --wait
docker compose --env-file .env.compose exec app node apps/api/dist/modules/accounts/cli.js seed-demo
node scripts/compose-smoke.mjs
```

Открыть http://localhost:3000. Compose запускает PostgreSQL, ждёт его готовности, выполняет миграции отдельным процессом и запускает сервер с собранным клиентом. База сохраняется в именованном томе. Порт приложения привязан к localhost; для размещения подключается HTTPS reverse proxy или HTTPS-вход хостинг-провайдера.

```bash
docker compose --env-file .env.compose restart app
node scripts/compose-smoke.mjs verify
docker compose --env-file .env.compose down
```

`down` без `--volumes` сохраняет данные. Не удаляйте том, если результаты нужны. Пароль для URL базы задавайте без символов, требующих URL-кодирования, либо используйте корректно закодированный `DATABASE_URL` при самостоятельном запуске.

Можно подключить собственный PostgreSQL без Docker: изменить `DATABASE_URL` в `.env`, применить миграции и запустить приложение. Для размещения собрать образ из `Dockerfile`, передать параметры как секреты окружения, отдельно выполнить `node apps/api/dist/db/cli.js migrate`, затем запустить сервер. Пример Compose предназначен для одного сервера; он не заменяет резервирование и проверку восстановления из задачи 14.
