# ЛУЧ — образовательная платформа

Исходный код демоверсии РКИ и английского. Реализуется последовательность задач из [плана разработки](docs/ROADMAP.md). Реализованы задачи **1–13: техническая основа, аккаунты, учебный контент, luch engine, анкета, диагностика, индивидуальный план, адаптация, повторения, главная ученика, аватары, текстовый и голосовой помощник, рабочий кабинет преподавателя, планировщик, браузерные видеозанятия, прогресс и учебный отчёт**. Доступны два маршрута по шесть мини-уроков, серверная проверка и сохранение ответов, состояние навыков и история причин изменения плана. Дополнительные варианты может создавать OpenAI или NeuroAPI. Распознавание голоса работает через ElevenLabs Scribe, listening и озвучивание ответов — через ElevenLabs TTS.

Основа: TypeScript, React/Vite, Fastify, PostgreSQL. Для локальной разработки PostgreSQL работает внутри процесса через PGlite и сохраняет данные на диск. На хостинге используется отдельный PostgreSQL через `pg`; API, SQL и миграции общие для обоих режимов.

## Быстрый запуск

Нужны Node.js 24 и npm 11. Docker для этого варианта не требуется.

```bash
git clone https://github.com/96-6/luchplatform.git
cd luchplatform
npm ci
npm run setup
npm run db:seed-demo
npm run db:smoke
npm run db:verify-smoke
npm run dev
```

Открыть **http://localhost:5173**. API: http://127.0.0.1:3000. В меню есть «Проверка системы»: сохранить запись и обновить страницу — запись остаётся в базе. Можно остановить приложение, запустить снова и проверить тот же список. `db:verify-smoke` читает запись, созданную `db:smoke`, уже в другом процессе.

`setup` подготавливает `.env`, добавляет недостающие параметры и применяет миграции. Существующие значения сохраняются; необходимые локальные ключи создаются автоматически. Данные хранятся в `data/luch`; эта папка и `.env` исключены из Git. Остановка — Ctrl+C.

**Для PGlite сначала остановите API, затем запускайте команды базы.** Разрешён один процесс на каталог базы; блокировка защищает от одновременного открытия CLI и сервером. Если нужен общий доступ нескольких процессов, используйте обычный PostgreSQL.

## Вход и демонстрационные аккаунты

После `db:seed-demo` доступны `student@example.test`, `teacher@example.test` и `admin@example.test`. Откройте «Демо-почта» со страницы входа и установите пароль по ссылке из письма. Войдите с почтой и паролем, отсканируйте QR приложением Authenticator и введите его код. Для дальнейшего входа нужны почта и пароль, затем отдельным шагом текущий шестизначный код. Демонстрационный преподаватель уже связан с демонстрационным учеником.

Обычная регистрация доступна ученикам и преподавателям: имя, почта и пароль от 12 до 128 символов, затем подтверждение почты и подключение Authenticator. Суперадмин создаётся серверной командой:

```bash
npm run admin:create -- --email your-address@example.com --name "Администратор"
```

В production письма отправляются через параметры `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`. Локальная демо-почта в production недоступна. Реальные почтовые доступы не включаются в репозиторий.

В кабинете суперадмина доступны аккаунты пользователей, назначения преподавателей, настройки безопасности и журнал действий. В карточке аккаунта показываются фактические числа прохождений и попыток. Раздел «Все прохождения» открывает ответы, подсказки, время и служебные данные любого пользователя. Управление чужим прохождением включается отдельно; автор таких действий сохраняется.

Команда создания суперадмина отправляет письмо для установки первого пароля. Если письмо устарело или аккаунт уже существовал, используйте «Установить или восстановить пароль» на странице входа.

Суперадмин может создать готовый аккаунт с почтой, начальным паролем и ролью, показать его QR Authenticator, задать новый пароль и сбросить 2FA. Созданный таким способом пользователь входит с почтой и паролем, затем подтверждает вход кодом; SMTP для этого не требуется. Сброс заменяет ключ и завершает прежние сессии. QR доступен только суперадмину в отдельном действии карточки аккаунта.

Пункт «Безопасность аккаунта» доступен всем ролям. Для смены пароля нужны текущий пароль и свежий код Authenticator; прежние сессии завершаются. При восстановлении по почте Authenticator сохраняется. Если утрачен второй фактор, его заменяет суперадмин. Старые аккаунты после миграции 018 устанавливают пароль через письмо или получают новый пароль у суперадмина; учебные данные сохраняются.

Пароли хранятся как защищённые хеши и недоступны для просмотра, включая суперадмина. Он управляет установкой и сбросом. Серверный `AUTH_ENCRYPTION_KEY` храните отдельно от базы, сохраняйте при обновлении и резервном копировании; не публикуйте его и не передавайте обычным администраторам. Доступ к PostgreSQL и серверному окружению ограничивается владельцем инфраструктуры; клиент и кабинет преподавателя не получают доступ к базе или хешам. Произвольная замена этого ключа сделает прежние защищённые данные непригодными.

Проверки обновления описаны в [протоколе авторизации](docs/ACCEPTANCE_PASSWORD_AUTH.md).

Изолированный отладочный вход включается серверным окружением только на localhost; production его запрещает. По умолчанию он выключен. Административное значение локального доступа хранится в окружении и не публикуется.

## Учебные материалы

`db:seed-demo` загружает аккаунты и учебный пакет без дубликатов. После входа откройте «Маршруты»: РКИ и английский, по шесть мини-уроков. Всего 12 навыков и 48 заданий: по 6 диагностических, 12 тренировочных и 6 контрольных заданий на язык. Материалы демонстрационные, с явной маркировкой.

Суперадмину доступен раздел «Учебный контент» с импортом и экспортом JSON. Каталог не передаёт ученику ключи ответов. Повтор импорта не дублирует материалы; новые редакции сохраняют прежние версии и результаты.

```bash
npm run content:validate -- --file content/demo/luch-demo.json
npm run content:import -- --file ./my-course.json
npm run content:export -- --package luch-demo --file ./luch-demo-export.json
```

Описание сущностей, блоков материала, медиа, версий и правил переноса — в [формате контента](docs/CONTENT_FORMAT.md). Для локального PGlite сначала остановите API перед импортом или экспортом.

## Прохождение урока

1. Войти учеником, открыть «Маршруты», выбрать язык и мини-урок.
2. В режиме «Тренировка» нажать кнопку начала, изучить материал, выбрать вариант или ввести короткий ответ.
3. Нажать «Проверить ответ»: luch engine проверяет ответ на сервере и сохраняет результат. В тренировке доступны подсказка, объяснение и новая попытка.
4. Перейти к следующему заданию. Для перерыва использовать «Сохранить и выйти».
5. После повторного входа открыть «Обучение» или сохранённый урок в кабинете. Восстанавливаются текущее задание, черновик, подсказки и история.

Диагностический и контрольный банки проходят без подсказок; ученик видит оценку и объяснения после завершения набора. «Пройти ещё раз» создаёт отдельный цикл, сохраняя прежние попытки.

Преподаватель читает прохождения закреплённых учеников. Суперадмин видит все прохождения и данные luch engine для отладки. Детали — в [описании движка](docs/ENGINE.md).

## Анкета и входная диагностика

1. В кабинете ученика открыть «Анкета и диагностика».
2. Выбрать РКИ или английский, цель, опыт и доступные минуты в день; сохранить анкету.
3. Начать короткую диагностику из отдельного банка выбранного языка. Сейчас это шесть демонстрационных заданий.
4. При перерыве использовать «Сохранить и выйти». После входа открыть «Продолжить диагностику»: текущий вопрос, черновик и ответы сохранены.
5. Завершить все задания и открыть результат по навыкам: сильные стороны в этом наборе, затруднения и явная отметка предварительной оценки.

Анкета сохраняется с версиями. Диагностика закрепляет снимок анкеты и редакцию банка; последующие изменения языка или цели не переписывают старый результат. Повторная диагностика создаёт новый цикл. Преподаватель ученика и суперадмин читают тот же сохранённый результат. После завершения диагностики автоматически сохраняется индивидуальный план с причинами назначений.

Структура данных и расчёт описаны в [DIAGNOSTICS.md](docs/DIAGNOSTICS.md).

## Первоначальный индивидуальный план

1. Завершить диагностику и нажать «Открыть индивидуальный план» на странице результата.
2. Посмотреть последовательность уроков, причины назначения и рекомендуемые дни с учётом доступного времени.
3. Нажать «Начать следующее назначение». Упражнения выполняются в том же luch engine с сохранением ответов и черновика.
4. После перерыва открыть «Мой план» → нужный план → «Продолжить назначенный урок».
5. Завершить урок и вернуться в план: статус и прогресс обновятся по фактическому завершению.

План закрепляет анкету, результат диагностики и редакцию банка. Повторное формирование не создаёт дубликаты; новая диагностика сохраняет отдельный план. Для результатов, полученных до этого обновления, на странице диагностики доступна кнопка формирования плана. Преподаватель читает планы закреплённых учеников; суперадмин видит и запускает любые назначения с записью автора.

При обновлении существующей установки остановить API, выполнить `git pull`, `npm ci`, `npm run setup`, затем `npm run dev`. Миграции 009–010 сохраняют прежние анкеты, попытки, диагностики и планы. Для собранного приложения дополнительно выполнить `npm run build` перед `npm start`.

Правила выбора, хранение и продолжение описаны в [PLANS.md](docs/PLANS.md).

## Адаптация, повторения и listening

После ошибки план добавляет упражнение на тот же навык. Успех с подсказкой или помощью учитывается отдельно и ведёт к самостоятельной практике. После самостоятельного успеха доступен следующий шаг и назначается отсроченная контрольная проверка; обычный срок — 48 часов. На странице плана показаны тип назначения, дата доступности, состояние навыков и история изменений с причинами. Повтор отправки ответа не дублирует назначения.

Данные восстанавливаются при запуске API. `npm run learning:recover` позволяет отдельно обработать сохранённые события (для PGlite сначала остановить API). Прежние попытки учитываются в навыках, без массового добавления назначений задним числом. Подробности — [ADAPTATION.md](docs/ADAPTATION.md).

Платные вызовы по умолчанию выключены, лимиты равны нулю. Суперадмин в «AI и расходы» задаёт ключи, модели, голоса ElevenLabs, подтверждённые верхние цены и общие ограничения. Администратор управляет адаптацией, listening, сроком повторения и рабочими лимитами в этих пределах; ключи и общие ограничения ему недоступны. Его готовый аккаунт создаёт суперадмин с ролью «Администратор». Вход по почте и паролю с отдельным подтверждением Authenticator открывает соответствующий кабинет.

Режим «дешевле» сравнивает верхнюю стоимость допустимых OpenAI/NeuroAPI по указанным ценам. Сбой генерации или исчерпание бюджета направляет к непросмотренному подходящему кэшу; при исчерпанном запасе показывается ошибка генерации контента. Сгенерированный вариант помечен как демонстрационный и проверяется тем же luch engine. В listening ученик подготавливает аудио ElevenLabs и слушает его в упражнении; сохранённое аудио используется повторно. Сбой озвучивания не создаёт неверный учебный ответ.

Учёт расходов охватывает вызовы этого приложения. Цены нужно сверять со своим тарифом; общий предел счёта также задаётся у поставщика. Описание настройки и ограничений — [PROVIDERS.md](docs/PROVIDERS.md).

## Аватары и помощник

Откройте «Помощник» и выберите Миру, Алекса или Искру. Сохраняются персонаж, голос для видео, обращение, темп, подробность и анимация. В упражнении работает «Демо-помощник»: объяснение, подсказка и короткий тематический диалог с историей после повторного входа. Контроль и диагностика разрешают только общие инструкции; учебная помощь отмечается в попытке.

Видео создаёт серверный адаптер HeyGen. Суперадмин в «AI и расходы» задаёт ID аватаров/голосов, ключ, движок, цену и лимиты. Готовые MP4 сохраняются и доступны без повторного платного вызова. Настройки и ограничения — [ASSISTANT.md](docs/ASSISTANT.md).

При отключённой генерации или исчерпанных средствах дополнительные задания используют ещё не просмотренный материал того же навыка. Когда подходящий запас просмотрен, показывается «Ошибка генерации контента»; назначение остаётся в плане, оценка не меняется. В маленьком демо-банке два тренировочных задания на навык, поэтому банк нужно пополнять или разрешать генерацию. История и явные повторения доступны независимо от этой ошибки.

Обновление применяет миграции до 016 без изменения прежних: остановить API, выполнить `git pull`, `npm ci`, `npm run setup`, затем `npm run dev`. Главная ученика подключена к этим данным задачей 8; новые миграции для неё не требуются.

## Голосовой ответ

В упражнении откройте «Голосовой ответ», разрешите микрофон, начните и завершите запись. Проверьте распознанный текст, при необходимости исправьте или запишите заново, затем нажмите «Подтвердить реплику и проверить». До подтверждения учебной попытки нет. Оценивается содержание подтверждённого текста; произношение отдельно не оценивается. Для задания с выбором можно явно указать соответствующий вариант.

Демо-помощник сохраняет обратную связь в чате и озвучивает её через ElevenLabs. Ошибка приводит к коррекции того же навыка по правилам задачи 7; самостоятельный успех — к следующему шагу и отсроченной проверке. Для закрытых наборов изменения применяются после завершения. Доступное назначение открывается кнопкой под ответом. Реплика, попытка, переписка и аудиокэш восстанавливаются после повторного входа.

Нужны HTTPS или localhost, совместимый браузер и серверная настройка ElevenLabs. В «AI и расходы» суперадмин задаёт ключ для `ElevenLabs Scribe STT`, модель `scribe_v2` или `scribe_v1`, верхнюю цену минуты, лимит записи (не более 30 секунд), бюджет и переключатель распознавания. Для TTS отдельно задаются модель, голоса RU/EN, верхняя цена символов и переключатель озвучивания помощника. По умолчанию вызовы выключены. Можно использовать `ELEVENLABS_API_KEY` на сервере как общий резервный ключ обоих подключений.

При отказе микрофона, STT или TTS доступны повтор и текстовый ввод. Техническая ошибка не снижает учебную оценку; сохранённый ответ не отправляется на повторную проверку при сбое звука. Пошаговая настройка, ограничения и хранение записи — [SPEECH.md](docs/SPEECH.md), проверки — [протокол задачи 10](docs/ACCEPTANCE_TASK_10.md).

## Расписание и видеозанятия

Планировщик `/schedule` показывает неделю, месяц и список в выбранном часовом поясе. Преподаватель создаёт индивидуальное или групповое занятие, меняет срок до начала и отменяет встречу. Встроенная комната использует открытый LiveKit: аудио, видео, экран, рука, чат, зал ожидания и управление участниками. Организаторы могут отключать медиа, удалять учеников, закрывать вход и завершать звонок для всех. Оранжевые значки предупреждают организаторов/суперадмина о возможном виртуальном активном устройстве; подробности доступны в комнате встречи.

Отдельная кнопка «Внеплановая встреча» создаёт встречу по одноразовой или многоразовой ссылке, с длительностью или без ограничения времени. Можно назначить время начала, срок действия ссылки и разрешить гостей без регистрации. Многоразовая ссылка подходит для нескольких участников и следующей новой встречи; прежняя история сохраняется. В чат можно отправлять файлы и изображения: по умолчанию до 125 МБ, файлы больше 50 МБ удаляются через 10 дней. Суперадмин меняет ограничения в «Настройках безопасности» → «Файлы в видеовстречах».

После встречи преподаватель сохраняет итог и назначает домашние упражнения в существующие планы. Ученик получает их в кабинете и проходит через прежний luch engine. Для полного локального комплекта: `node scripts/setup.mjs --compose --video`, затем `docker compose --env-file .env.compose --profile video up --build -d --wait`. Настройка собственного сервера/HTTPS/TURN, ограничения браузеров и списки имён — [MEETINGS.md](docs/MEETINGS.md), проверки — [протокол задачи 12](docs/ACCEPTANCE_TASK_12.md).

В «Настройках безопасности» → «Защита видеовстреч» суперадмин может включить «Защита от записи видеозвонка». По умолчанию режим выключен. Он добавляет персональные водяные знаки на камеры и демонстрации, ограничивает меню видео, картинку в картинке и печать. Настройка действует и для гостей, текущие звонки получают её при следующем обновлении состояния. **Это меры сдерживания, а не DRM: браузер не гарантирует запрет OBS, системной записи, скриншотов и съёмки другим устройством на компьютере или телефоне.** Обновление требует миграции 020 через `npm run setup` перед запуском API. Проверки — [протокол защиты видеовстреч](docs/ACCEPTANCE_MEETING_RECORDING.md).

## Работа преподавателя

В кабинете преподавателя откройте закреплённого ученика: цель, диагностика, план, последние ответы и подсказки доступны в общей карточке. На странице конкретного ответа можно оставить комментарий, подтвердить текущую оценку или исправить её. Исходная автоматическая оценка сохраняется рядом с историей проверок; текущая оценка учитывается в главной и состоянии навыка. Диагностика/контроль сначала должны быть завершены учеником.

На странице плана преподаватель назначает точное упражнение закреплённого маршрута, указывает причину и дату доступности. Ещё не начатое назначение можно перенести или отменить. Ученик видит изменения на главной, в `/feedback` и в истории плана; отмена не считается выполнением урока. Все действия сохраняются с автором, датой и защитой от повторной отправки. Начало урока и ответы остаются действиями ученика.

Инструкция — [TEACHER.md](docs/TEACHER.md), проверки — [протокол задачи 11](docs/ACCEPTANCE_TASK_11.md). Новые ключи внешних сервисов для кабинета не нужны.

## Главная ученика

После входа ученик попадает на `/student`; пункт «Главная» и адрес `/` открывают этот же экран. Здесь видны язык, цель и нагрузка из сохранённой анкеты, незавершённые задания на сегодня, назначенные повторения, краткий прогресс и последние пять результатов. Новый аккаунт начинает с анкеты, затем запускает диагностику с главной. После диагностики основная кнопка открывает первое назначение из существующего плана.

«Продолжить урок →» возвращает в последнее активное прохождение выбранного языка с теми же ответами и черновиком. Без активного урока предлагается коррекция, самостоятельная практика, готовое повторение или следующий шаг. Задания на сегодня учитывают рекомендованный день плана и часовой пояс браузера; незавершённые задания предыдущих дней остаются видны. Будущие контрольные повторения показываются с датой и открываются только в назначенное сервером время.

Сводка разделяет самостоятельные ответы, помощь и ошибки. Оценки незавершённой диагностики и контроля остаются скрытыми до завершения. Переходы к плану, помощнику, расписанию и полному учебному отчёту работают. Подробные правила — [DASHBOARD.md](docs/DASHBOARD.md), проверка — [протокол задачи 8](docs/ACCEPTANCE_TASK_8.md).

Обновление существующей установки: остановить API, выполнить `git pull`, `npm ci`, `npm run setup`, затем `npm run dev`. Прежние данные и миграции сохраняются. Для собранного запуска выполнить `npm run build` перед `npm start`.

## Прогресс и учебный отчёт

Откройте «Прогресс» (`/progress`). Отчёт показывает фактические попытки и выполненные задания, самостоятельные результаты, помощь и текущие подтверждения/исправления преподавателя, состояние навыков, повторные ошибки и причины изменений плана. Следующие шаги открывают существующие назначения; страница обновляется после новых результатов автоматически.

Преподаватель открывает тот же отчёт из карточки ученика. Только он и суперадмин дополнительно видят сохранённый контекст честности, условные веса и их вклад в свидетельства самостоятельного результата. Учебный балл от этих весов не меняется; отсутствие наблюдений не считается нарушением. Языки и редакции банка разделены, оценки незавершённых диагностик/контроля не раскрываются через сводку.

Устройство — [REPORTS.md](docs/REPORTS.md), проверки — [протокол задачи 13](docs/ACCEPTANCE_TASK_13.md). Обновление применяет миграцию 015 с индексами, сохраняя прежние таблицы и данные. Дополнительные внешние сервисы не требуются.

## Интерфейсы и обслуживание

В `/operations` администратор и суперадмин видят фактическое состояние и готовые очереди, могут повторить обработку учебных событий и команд видео. Суперадмину также доступны загрузка демобанка и очистка истёкшего сырого аудио. Результаты операций сохраняются; повтор не создаёт второе действие. Аккаунты, 2FA, материалы, бюджеты/ключи и закрепление/снятие преподавателей управляются через кабинеты. Прежние консольные команды остаются для установки и аварийного восстановления.

Меню проверено для всех ролей; преподаватель выбирает ученика для плана, анкеты, помощника и отчёта в интерфейсе. Прямые и временные ссылки проверяются на сервере и при переходе внутри приложения, в том числе в режиме Vite: ошибки получают 400/401/403/404/410 по условию. Сохранённые собственные уроки и планы работают после повторного входа. Обновление добавляет миграцию 016 без изменения прежних данных.

Правила — [INTERFACES_ACCESS.md](docs/INTERFACES_ACCESS.md), проверки — [протокол](docs/ACCEPTANCE_INTERFACE_ACCESS.md).

## Язык интерфейса и статусы аккаунта

Внизу меню находится переключатель русского и английского интерфейса. По умолчанию используется язык браузера; ручной выбор сохраняется. Учебный язык выбирается отдельно в анкете. Каталоги и добавление локализаций — [LOCALIZATION.md](docs/LOCALIZATION.md).

В карточке аккаунта суперадмин может отключить «Аккаунт активен» либо установить блокировку с причиной. Пользователь увидит «Ваш аккаунт деактивирован администратором» или «Ваша учетная запись заблокирована» и причину. Отключение завершает текущие сессии; восстановление сохраняет прежние ключи и учебные данные. Обновление требует применения новой миграции 017 через `npm run setup` перед запуском API.

Изменения оформления ошибок, приватные жёлтые отметки ответов и видеокомната описаны в [протоколе](docs/ACCEPTANCE_UI_LOCALIZATION.md).

## Параметры доступа

Капча и проверка сетевого доступа переключаются суперадмином. Доступ в ограниченном режиме зависит от проверки аккаунта и белого списка IP. При срабатывании сетевой проверки сайт и API возвращают отказ с сообщением «вы используете VPN - сервис недоступен».

Для размещения задаются доверенные адреса reverse proxy в `TRUST_PROXY_CIDRS`; дополнительный серверный источник сетевых данных подключается через `IP_INTEL_URL` и `IP_INTEL_KEY`. Неполученные измерения остаются неизвестными. Классификация соединения не является доказательством использования VPN.

При потере доступа после изменения сетевых настроек оператор сервера может выполнить `npm run security:reset` (для локальной базы сначала остановить API). Настройки и реальные секреты окружения не публикуются.

Фоновая проверка прохождения переключается в настройках безопасности суперадмина. Контекст попытки доступен преподавателю ученика и суперадмину. Пометки требуют проверки человеком и не изменяют учебную оценку автоматически. Неполученные наблюдения не считаются нарушением.

## Конфигурация

Полный пример — [.env.example](.env.example). Сервер читает `.env` в корне проекта; переменные процесса имеют приоритет. Неизвестное значение флага, неверный порт или адрес приводят к отказу запуска с названием проблемного параметра.

| Параметр                                                   | Назначение                                                                                         |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `APP_ENV`                                                  | `development`, `test` или `production`                                                             |
| `APP_URL`                                                  | Полный origin приложения; разрешённый адрес браузерных запросов                                    |
| `API_HOST`, `API_PORT`                                     | Адрес и порт API; в контейнере host `0.0.0.0`                                                      |
| `WEB_PORT`                                                 | Порт Vite в разработке                                                                             |
| `DATABASE_URL`                                             | `pglite:./data/luch` локально или `postgresql://user:password@host:5432/luch`                      |
| `DATABASE_SSL`                                             | `true` для TLS к внешней базе с проверкой сертификата                                              |
| `ENABLE_DEV_TOOLS`                                         | Тестовые записи и проверка системы; по умолчанию выключены                                         |
| `LOCAL_DEBUG_LOGIN`                                        | Изолированный локальный режим; по умолчанию выключен, production запрещён                          |
| `LOCAL_DEBUG_ADMIN_ALIAS`                                  | Локальное значение доступа из окружения; не включается в репозиторий                               |
| `SERVE_WEB`                                                | Раздача собранного клиента сервером                                                                |
| `LOG_LEVEL`                                                | `debug`, `info`, `warn`, `error`, `silent`                                                         |
| `OPENAI_API_KEY`, `NEUROAPI_API_KEY`, `ELEVENLABS_API_KEY` | Необязательные серверные ключи; приоритет имеет настройка суперадмина в базе                       |
| `AI_API_URL`, `AI_API_KEY`                                 | Резервные поля совместимости; текущие подключения настраиваются в кабинете                         |
| `SPEECH_API_URL`, `SPEECH_API_KEY`                         | Зарезервированы; адаптеры ElevenLabs используют `ELEVENLABS_API_KEY`                               |
| `VIDEO_SERVICE_URL`, `VIDEO_API_KEY`                       | Резервные поля; встречи используют LIVEKIT_URL и связанные параметры                               |
| `LIVEKIT_URL`, `LIVEKIT_WS_URL`                            | Внутренние HTTP/WS-адреса SFU; браузеры используют шлюз приложения                                 |
| `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`                    | Серверные ключи собственного LiveKit; подготовка через `setup --video`                             |
| `MEETING_FILE_DIRECTORY`                                   | Закрытый постоянный каталог вложений; по умолчанию `data/meeting-files`, в Compose — отдельный том |
| `LIVEKIT_NODE_IP`                                          | Адрес медиа для локальной конфигурации; на хостинге см. [MEETINGS.md](docs/MEETINGS.md)            |

Без ключей и бюджетов адаптация работает из банка, внешние сервисы не вызываются. Ключи клиенту не передаются. Для production обязательны отдельный PostgreSQL, HTTPS в `APP_URL`, `ENABLE_DEV_TOOLS=false`, постоянный `AUTH_ENCRYPTION_KEY` и настроенный SMTP (`MAIL_MODE=smtp`). Рабочий URL, TLS и аккаунты хостинга подключаются на этапе размещения.

## PostgreSQL и контейнеры

```bash
node scripts/setup.mjs --compose
# Задать POSTGRES_PASSWORD в .env.compose.
docker compose --env-file .env.compose up --build -d --wait
docker compose --env-file .env.compose exec app node apps/api/dist/modules/accounts/cli.js seed-demo
node scripts/compose-smoke.mjs
```

Открыть http://localhost:3000. Compose запускает PostgreSQL, ждёт его готовности, выполняет миграции отдельным процессом и запускает сервер с собранным клиентом. База сохраняется в именованном томе. Порт приложения привязан к localhost; для размещения подключается HTTPS reverse proxy или HTTPS-вход хостинг-провайдера.

```bash
docker compose --env-file .env.compose restart app
node scripts/compose-smoke.mjs verify
docker compose --env-file .env.compose down
```

`down` без `--volumes` сохраняет данные. Не удаляйте том, если результаты нужны. Пароль для URL базы задавайте без символов, требующих URL-кодирования, либо используйте корректно закодированный `DATABASE_URL` при самостоятельном запуске.

Можно подключить собственный PostgreSQL без Docker: изменить `DATABASE_URL` в `.env`, применить миграции и запустить приложение. Для размещения собрать образ из `Dockerfile`, передать параметры как секреты окружения, отдельно выполнить `node apps/api/dist/db/cli.js migrate`, затем запустить сервер. Пример Compose предназначен для одного сервера; он не заменяет резервирование и проверку восстановления из задачи 14.
